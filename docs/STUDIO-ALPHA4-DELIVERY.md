# Forterm Studio 0.4.0-alpha.4 交付说明（2026-11-23）

补齐连接编辑表单截图里剩下的项，并给隧道加上动态转发（SOCKS）。计划和决定见 `docs/STUDIO-REBUILD-PLAN.md`，上一版见 `docs/STUDIO-ALPHA3-DELIVERY.md`。alpha.3 及更早的包、检查点都没有改动；alpha.36（`Forterm.Desktop`）的源码没有改动，只是重新编译确认仍能通过。

## 内容

### 连接编辑表单（对照截图 04、05）

- **Cipher 算法 / 密钥交换算法**（“其他设置”）：
  - 下拉列表来自 SSH.NET 实际支持的算法。老旧算法（CBC、3DES、SHA1 系列的 DH）标注“较弱，仅老旧服务器”。
  - 选中的算法排到客户端提议的**第一位**，其余算法保留原顺序，不删除任何算法。所以服务器不支持所选算法时，按默认顺序照常协商，不会因此连不上。
  - 未知名称在连接前就拒绝，不发起网络连接。连接库文件里出现本版本不支持的名称（例如以后 SSH 库移除了某个算法）时，按“默认”处理，不会让整个连接库无法读取。
  - 只对 SSH/SFTP 连接生效；跳板链上每一跳各用自己连接里的设置。控制器唤醒的临时会话不使用任何偏好。
- **主机密钥算法：按审查意见没有做**（截图里有这一项）。现有指纹库每个“主机:端口”只存一个指纹；同一台主机一会儿用偏好、一会儿用默认顺序（比如控制器唤醒），出示的主机密钥类型不同，每次都会弹“主机指纹已变化”，等于训练用户点过中间人攻击警告。要做需要先让指纹库按密钥类型分别保存，这要改 Core 里与 alpha.36 共用的指纹库，留待以后。
- **禁止列表监控开启**（“其他设置”）：开启后，连接列表的“信息”列不显示这台主机的 CPU/内存/磁盘，它的监控栏默认改为手动刷新，不再自动执行采集命令。手动刷新仍可用。
- **会话环境变量**（“初始化”）：
  - 每个交互终端通道在 pty 请求之后、shell 请求之前，按 SSH 协议发送 `env` 请求（RFC 4254 6.4）。**不向终端写入任何内容**，也不会在被拒绝时改用 `export`。
  - 同一连接的每个终端页签都会发送；监控、sudo 等 exec 通道不发送。控制器唤醒的临时会话不发送。
  - 服务器只接受其策略允许的变量名（OpenSSH 的 `AcceptEnv`，默认通常只有 `LANG`、`LC_*`）。未被接受的变量名会显示在工作区状态里，终端照常打开。
  - 校验：变量名只能是字母、数字、下划线，不能以数字开头，最长 64；值最长 1024，不能含换行或控制字符；最多 32 个；不能重名。表单里完全空白的行会被忽略。
  - 值以明文保存在本机连接库（与“初始执行”相同），表单提示写明“请勿填写密码或令牌”。
  - **导出连接时不包含环境变量**。导入时丢弃文件里的环境变量和算法偏好，和“初始执行/保活命令”一样计入导入提示：他人文件不能给本机已认证的 shell 设置环境，也不能把弱算法排到首位。
- **X11 转发和 X11 Cookie 模式没有做**：SSH.NET 不支持 X11 通道，表单里不放无效的开关。

### 隧道：动态转发（SOCKS）

- 新建隧道可以选“本地转发（到固定目标）”或“动态转发（SOCKS 代理）”。
- 动态转发在 127.0.0.1 上提供 SOCKS4/5 代理（不需认证），每个客户端连接在隧道自己的 SSH 连接上开一个 direct-tcpip 通道。服务器拒绝转发时，SOCKS 客户端收到失败应答，隧道继续运行。
- 与本地转发相同：只监听 127.0.0.1，手动启停，断开后不自动重连，同一本地端口不能被两个隧道使用。
- 注意：本机任何程序，以及多人同时登录的 Windows（如远程桌面服务器）上的其他用户，都可以经这个 SOCKS 代理访问服务器所在网络。对话框里写明了这一点，并提示这类机器上不要使用。
- 隧道配置里动态转发残留的远程地址/端口字段会被忽略，不会让连接库无法读取。
- 停止隧道（本地或动态）改在后台关闭转发和连接，不再可能让界面卡住到连接超时。
- 没有做远程转发（`-R`）：它需要 SSH 全局请求，而现有协议保活假定同一时间只有一个全局请求在等待应答。

### 修复

- **非法终端类型会让“保存”抛出未处理异常**（alpha.3 起就有）：例如终端类型填 `xterm 256` 后点保存，校验抛出的是 `ArgumentException`，保存按钮的处理只接住 `InvalidDataException`，异常会冒到界面线程，可能导致程序退出。现在统一转换成表单错误提示。

### Core 与 vendor 改动（均为新增）

- `Forterm.Core`：
  - 新文件 `SshAlgorithms.cs`：算法列表、偏好校验与应用、`SshNegotiated`、`ShellEnvironment` 校验。
  - `SessionConnectOptions` 新增 `PreferredKeyExchange`、`PreferredCipher`，默认空字符串，行为与之前完全相同。
  - `SharedSshSession`：`Negotiated`（实际协商的算法；密钥交换报的是实现名，`curve25519-sha256@libssh.org` 会显示为 `curve25519-sha256`）、带环境变量的 `OpenShellAsync` 重载、`ForwardDynamic`；`LocalForward` 改为可承载本地或动态转发，公开成员不变。
  - `SshPtyConnection.RejectedEnvironment`。
- `vendor/SSH.NET`：`ShellStream` 新增一个内部构造函数，`SshClient` 新增一个公开的 `CreateShellStream` 重载，用来在 shell 请求前发送 `env` 请求。原有方法没有改动。`vendor/patches/sshnet-shared-transport.patch` 已同步新增这两个文件的差异，并用上游副本核对过能逐字节还原当前文件。
- 测试夹具 `tooling/ssh_fixture.py`：
  - 新开关 `FIXTURE_ACCEPT_ENV=名称,名称`：接受这些环境变量名，其余拒绝。没有设置时与以前一样全部拒绝。
  - `stats` 新增 `env`（每个请求的通道、名称、值、是否接受、是否在 shell 之后）和 `negotiated`（服务器侧协商结果：密钥交换的确切名称、主机密钥、Cipher）。

## 未验证 / 限制

- 与 alpha.3 相同，以下都没有运行过：Windows 实机（ConPTY、DPI、输入法）、真实控制器唤醒和堡垒机、Windows 凭据管理器和 Mac 钥匙串的真实读写。Windows CI 工作流仍未运行（代码没有提交推送）。截图都是软件渲染。
- 环境变量、算法偏好、SOCKS 只在 paramiko 回环夹具上验证过，没有对真实 OpenSSH 或堡垒机验证。
- `env` 请求按协议要求应答，逐个往返。不按协议应答的服务器会让终端在连接超时后打开失败，这时请删掉该连接的环境变量。变量多、跳板链长时，打开终端会稍慢。
- 动态转发（SOCKS）不需认证。本机任何程序和多人登录的 Windows 上的其他用户都能使用它访问服务器所在网络；本地转发同样能被连接，只是目标固定。上游 SSH.NET 读取 SOCKS4 用户名时没有长度上限（只影响本机连接）。
- 程序退出时，运行中的隧道在后台关闭，进程可能先退出，服务器那边只看到 TCP 断开，没有 SSH 断开消息。
- **退回 alpha.3**：Studio 各版本共用一个数据目录。配置过动态转发隧道后再运行 alpha.3，alpha.3 会把它当成没有远程地址的本地转发而拒绝读取整个连接库。alpha.3 这时改用临时空连接库，原文件不会被改动；回到 alpha.4 即恢复。需要回退时，先在 alpha.4 里删除动态转发隧道。没有动态转发时 alpha.3 能读取，但它一旦保存连接库，会丢掉 alpha.4 新增的字段（会话环境变量、算法偏好、禁止列表监控）。
- 没有做：主机密钥算法偏好（原因见上文）、X11 转发和 Cookie 模式（SSH.NET 不支持）、远程转发（与协议保活的全局请求假定冲突）、RDP/VNC。
- `Forterm.Tests` 有 1 次未查明原因的偶发失败，见“验证”。
