# Forterm Studio 0.4.0-alpha.10 交付说明（2026-11-26）

本版做的是 alpha.9 交付后列出的“还差什么”里的第 3、4 类（用户 11-26：“第3、4类都做”）：参考截图里还没做的设置项，和已知的小缺口。计划和决定见 `docs/STUDIO-REBUILD-PLAN.md`，上一版见 `docs/STUDIO-ALPHA9-DELIVERY.md`。

Core、vendor 的终端控件和 xshell / xftp 入口有改动，`Forterm.Desktop` 的行为不变（见“改动范围”）。`Forterm.Desktop` 的源码、alpha.9 及更早的包、预览包和检查点都没有改动。

更正：上次列的“编辑器里手动选的语言不保存”在 alpha.8 已经做了（按扩展名记住，没有扩展名的按文件名，最多 100 种），是我列错了，本版没有再改。

## 内容

### 锁屏（新，系统配置 → 锁屏）

- **设置密码**：至少 4 个字符。修改和移除都要先输对现在的密码。密码只以加盐的慢哈希（PBKDF2-SHA256，30 万轮）存放在系统钥匙串 / 凭据管理器里，不在设置文件和备份里。
- **锁定的方式**：
  - 手动：快捷键（macOS ⌘⇧L，其他系统 Ctrl+Shift+K，可在“快捷键”里改），命令面板“锁定 Forterm”，或设置页的“立即锁定”；
  - 自动：多久没有在 Forterm 里按键、点击或移动鼠标后锁定（不自动 / 5 / 10 / 15 / 30 / 60 分钟）；
  - 启动时锁定：程序一启动就锁定，控制器唤醒的会话照常打开，解锁后才看得到。
- **锁定时**：
  - 所有 Forterm 窗口都被遮住，下面的内容是隐藏的，屏幕阅读器也读不到、按不到；
  - 按键、文字输入、点击、拖放都到不了会话，窗口自己的快捷键和命令面板也不响应；
  - 打开着的菜单、下拉列表、提示会关掉；锁定期间新弹出的窗口（例如唤醒时的主机指纹确认）也被遮住；
  - 有对话框开着时，对话框里也能解锁（对话框开着时主窗口接收不到按键）；
  - 系统的文件选择框遮不住：锁定之后它返回的结果不使用；
  - 主窗口不能关闭（提示先解锁）；
  - 会话照常保持：协议心跳、空闲保活、传输都继续。
- **解锁**：输对密码；连续输错 5 次后每次都要等待，从 30 秒加倍到最多 5 分钟。解锁后键盘回到锁定前的地方。
- **忘记密码**：只能在锁屏上“退出 Forterm”（要点两次确认），所有会话都会断开。要去掉锁屏密码，可以在系统钥匙串（Windows 为凭据管理器）里删除 Forterm Studio 的 `studio/lock/verifier` 一项。
- 从别人的备份恢复设置时，自动锁定和启动时锁定保持本机的，不会被关掉。

### 自定义背景图片、全局不透明度（系统配置 → 主题界面）

- **背景图片**：显示在主窗口各栏和终端后面，“图片透出”10%–90%。
  - 图片复制到数据目录：最长边不超过 3840 像素，重新存成 PNG（不带拍摄地点等附加信息），之后不再读原文件。备份里不含图片。
  - 拒绝的情况：超过 32 MiB、超过 4000 万像素或边长超过 16384 的图片，以及认不出来的文件。
  - 对话框、菜单、输入框和锁屏保持不透明。
- **全局不透明度**：主窗口整体（含终端）30%–100%，设置窗口和对话框不变。
- 参考截图里的“全局透明度（Beta）”（纯透明窗口）没有做。

### 页签位置、标签渲染（系统配置 → 布局）

- **页签位置**：终端栏（终端和编辑器）的页签放在上面或下面，所有会话立即生效，包括本地终端。
- **标签渲染**：
  - 显示时再开始（默认，和以前一样）：还没显示过的终端（后台会话、没点开的页签），输出先在连接里等着，超过约 2 MiB 后服务器暂停发送，正在运行的命令会停下来，直到你切换过去；
  - 立即开始：每个终端一打开就接收和处理输出，后台的命令不会被暂停，多占一些内存。

### 已知小缺口的补齐

1. **粘贴可以停止**：服务器一直不接收时，粘贴不到 1 秒就出现“正在粘贴：服务器还没有收完”和“停止粘贴”。停止后，已经发出的部分留在终端里，其余的不再发送。如果程序要求了括号粘贴模式，会补上结束标记，否则之后打的字会被 shell 当成粘贴内容。一次只粘贴一份：上一份没发完时，再粘贴会被拒绝并说明。粘贴和前后打的字保持原来的顺序。
2. **快速命令写入失败时如实说明**：以前写入失败、但通道看着还在时，状态栏仍显示“已输入”。
3. **空闲保活认得更多提示符**（“回车”方式）：以 `❯` 结尾的（starship、pure）、oh-my-zsh 默认主题的 `➜`、Windows cmd / PowerShell 和 fish 的 `>`，以及 zsh 右侧另有提示（时间、目录）的情况。不认：单独的 `>`、`>>`、`quote>` 这类续行提示，`mysql>`、`Opt>` 这类菜单，带问号的问题。
4. **终端查找**：只在内容变了（有新输出、尺寸变了、清空了）时才重新扫描回滚，翻上一个 / 下一个不再每次重扫。
5. **编辑器正则支持前后查看、反向引用**：能用线性时间引擎的照旧，用不了的改用回溯引擎，同样有时间上限，太慢时停下并说明。
6. **关闭保护按窗口分别计算**：一个窗口里刚关掉东西，另一个窗口的 × 不再跟着不响应。
7. **跳板机断开时说是跳板机**：经跳板机连接时，如果是跳板机先断开，说明和连接诊断写“跳板机的连接先断开了：……（跳板机的说明）。经它到这台服务器的连接也随之中断”，多级时写第几级。目标服务器自己断开时照旧。诊断里跳板机的说明同样隐去地址、名称和密码。
8. **入口被隐藏启动时，失败说明仍然看得见**：控制器用隐藏窗口启动 xshell / xftp 时，入口失败的说明框以前可能看不见。现在会先让一个零尺寸的窗口承接系统的“隐藏”要求，说明框正常显示并置顶。只在 Windows CI 上实测。

## 独立代码审查

打包前做了一轮独立审查（11-26，审查者在仓库的副本里写测试实测）：2 项高危、2 项中危、3 组低危，全部修改；除了系统文件选择框和 Core 那一项（见“验证”里的变异测试），每项都加了测试。第 1 行那一项我在审查进行中也发现了，审查者开始读代码时它还在。

| 等级 | 问题 | 处理 |
|---|---|---|
| 高 | 设了背景图片时，锁屏的底色是半透明的，下面的会话内容会隐约透出来（审查开始时的版本） | 锁屏和其他窗口的遮罩一律用不透明的底色 |
| 高 | 锁定时下面的界面只是被盖住：屏幕阅读器（VoiceOver、讲述人）仍能读出页签、主机、文件名，还能按下面的按钮（关闭会话、命令面板）。审查者用自动化接口实际打开了命令面板 | 锁定时下面的内容整体隐藏，不只是遮住；测试检查自动化树里已经没有下面的按钮，只有锁屏的密码框 |
| 高 | 锁定时如果有对话框开着（连接编辑、粘贴确认、主机指纹确认等），主窗口被对话框挡着接收不到按键，对话框上只有“请在主窗口解锁”，只能结束进程 | 每个窗口的遮罩都是完整的锁屏，在对话框里也能解锁；键盘交给最前面窗口的锁屏 |
| 中 | “标签渲染”的隐藏位置只有一个，属于最新打开的主窗口：开了第二个主窗口或那个窗口关闭时，正在其中排版的终端显示出来会抛出“已有父元素”的异常（程序退出） | 每个主窗口有自己的隐藏位置，按名字认出并取出；窗口关闭时先放开里面的终端 |
| 中 | 锁定时系统的文件选择框遮不住，选中的文件照样会上传或下载 | 锁定期间或锁定之后返回的选择结果一律不用 |
| 低 | 粘贴绕过了终端自己的输入顺序，服务器不接收时，粘贴前打的字可能排到粘贴后面；停止后按钮还在但不起作用；停在开头标记中间时会留下半个转义序列；锁定时打开着的菜单、提示还画在锁屏上面；双击“退出 Forterm”会一次通过两步确认 | 粘贴和打字按原来的顺序发送；停止后提示条立即消失；开头标记整段发送；锁定时关闭菜单、下拉列表、提示；第二次点击要隔开一点时间 |
| 低 | Core：本连接已经因为自己的原因结束后，后到的事件仍可能把原因改记成跳板机 | 连接已经结束后不再改记 |
| 低 | 背景图片先检查尺寸再重新打开解码，中间换了文件就绕过了检查；只限制了宽度，很高的图片仍会占大量内存；文件名检查接受结尾的换行 | 只读一次；长边都不超过 3840；名称检查改严 |

审查者确认没有问题的部分：锁定时的按键、文字输入和输入法提交，主窗口快捷键和命令面板，设置窗口的按键，锁定时拒绝关闭，拖放，锁屏密码的保存和校验、输错后的等待，不受信任的备份恢复，粘贴的取消和异常处理，提示符识别（输入到一半时不发回车），编辑器正则的时间上限，终端查找，Core 没有嵌套锁、`Forterm.Desktop` 不受影响，入口程序的 `STARTUPINFO` 结构和调用。

没有改的：关闭保护现在只记“用户最后操作的那个窗口”，如果某个页签在主窗口里自己消失、而用户最后操作的是设置窗口，主窗口这次不受保护（页签不会自己消失，目前没有这种情况）。

## 改动范围

- Studio（`avalonia/src/Forterm.Studio`）：
  - 新增 `Services/AppLock.cs`、`Views/LockView.axaml(.cs)`（锁屏），`Services/Backdrop.cs`（背景图片），`Services/TerminalWarmUp.cs`（标签渲染）；
  - 设置项和设置页（主题界面、布局、新的“锁屏”分类），主窗口（背景、不透明度、锁屏层、隐藏位置），终端栏（页签位置、停止粘贴的提示条），快捷键和命令面板（锁定），备份恢复（锁屏设置不被别人的备份关掉），凭据存储（锁屏密码的校验值），系统文件选择框（锁定后的结果不用）；
  - 粘贴、快速命令、空闲保活提示符、终端查找、编辑器正则、关闭保护、跳板机的诊断各自的改动见“内容”。
- Core（与 `Forterm.Desktop` 共用，只增不改）：`SshTrace.UpstreamEnded`；`SharedSshSession` 只在有诊断记录（只有 Studio 有）时检查跳板机是否先断开。`Forterm.Desktop` 没有诊断记录，行为不变；旧测试 241 项通过，Desktop 构建 0 警告。
- vendor 终端控件（`Iciclecreek.Terminal`，补丁标识 `paste-sender-v18`）：新增 `PasteSender`，默认为空，此时行为与以前完全相同（`Forterm.Desktop` 不设置它）。补丁记录 `FORTERM.patch` 按上游原文件重新生成，并核对过还原后与上游的哈希一致、重新应用后与现在的文件一致。
- xshell / xftp 入口（`Forterm.Launcher`）：隐藏启动时让说明框可见，说明框置顶。
- 工具和 CI：`tooling/check-entry-hidden.ps1`（新），`native-check.py --looks`（新），CI 各加一步。
- 版本 0.4.0-alpha.10；数据目录不变（`LocalAppData/Forterm/Studio`）。
- **退回 alpha.9**：alpha.9 能读取设置文件，但一旦保存会丢掉本版新增的设置（锁屏的自动锁定和启动时锁定、背景图片、不透明度、页签位置、标签渲染）。锁屏密码的校验值留在系统凭据库里，alpha.9 不读它；背景图片的副本留在数据目录里。

## 未验证 / 限制

- **真实堡垒机“登录后断开”的原因仍未确定**，还在等 alpha.9 或本版的“复制连接诊断”。
- 以下都没有运行过：Windows 10/11 桌面实机（安装包的 SmartScreen 和杀毒软件、ConPTY、DPI、输入法、AltGr、真实拖放）；真实控制器唤醒；Windows 凭据管理器和 Mac 钥匙串的真实读写（**锁屏密码就存在这里**，只用内存里的模拟凭据库测过）；真实的屏幕阅读器（只用 Avalonia 的自动化接口检查过）。
- 锁屏：
  - 系统文件选择框盖不住，只是锁定之后它返回的结果不用；
  - 锁定期间唤醒的会话照常连接，如果要确认主机指纹或回答键盘交互问题，要等解锁后才能回答，期间可能超时（45 秒）而失败，需要从控制器重新发起；
  - 锁定期间，后台终端的“立即开始”要等解锁后才开始；
  - 关闭保护现在只对用户最后操作的窗口生效（见审查表下的说明）。
- 背景图片和全局不透明度只在 macOS 实机和 Windows Server 虚拟机上看过；“全局透明度（Beta）”没有做。
- 粘贴：服务器一直不接收时，“停止粘贴”之后结束标记要等服务器收下才发得出去；停止时如果正好在一个多字节字符中间，服务器会收到半个字符。
- 入口隐藏启动的处理只在 Windows CI 上实测。
- 安装包没有数字签名。
- 其他限制见 `docs/STUDIO-ALPHA4-DELIVERY.md` 到 `docs/STUDIO-ALPHA9-DELIVERY.md`。
