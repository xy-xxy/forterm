# Forterm Studio 0.4.0-alpha.15 交付说明（2026-11-27）

用户 11-27 在真实门户上用过 alpha.13（登录、列出资产、打开终端都成功）后提的四件事：堡垒机单独做一个标签；终端已经打开了，堡垒机窗口过很久才显示“已打开”；账号下拉可以维护，用户名、密码只维护一次并记住选择；“关联已打开的文件会话”点了没反应。计划和决定见 `docs/STUDIO-REBUILD-PLAN.md`，上一版见 `docs/STUDIO-ALPHA13-DELIVERY.md`。

中间打过一个 0.4.0-alpha.14（提交 f4a2f84），还没交付就在 Windows 检查里发现“关联”按钮的真正原因，改为 alpha.15；alpha.14 的包已删除，本说明包括两版的全部改动。

Core、vendor 没有改动，`Forterm.Desktop` 不受影响。

## 内容

### 1. 连接库的“堡垒机”标签

- 连接库顶部（SSH、FTP、Telnet 之后）新增“堡垒机”标签。左边是堡垒机账户列表（名称、用户名和租户，已登录的有小绿点）；右边是选中那个堡垒机的机器，和普通连接列表一样的表格：系统、名称、地址、账号、打开（SSH / SFTP），可搜索（由堡垒机查找，输入停顿后自动搜索）、刷新、翻页，双击一行打开终端。
- 选中一个账户只显示它的门户、租户和用户名，点“登录”（或双击左边的账户）才访问门户。每个账户的登录在程序运行期间一直保留，切换标签、切换账户都不用重新登录；删除账户或关闭程序时注销。
- 左上角“钥匙”按钮打开“堡垒机账户”（编辑、删除、动态口令），“+ 账户”直接新建。“堡垒机账户”里的“登录堡垒机”现在跳到这个标签并登录。原来单独的“堡垒机资产”窗口去掉了。

### 2. 打开会话后马上显示“已打开”

- **原因**：资产窗口要等整个会话连完才显示结果，而这台堡垒机在终端连接上不回应文件通道，要等到超时。
- 现在终端（SSH）或文件（SFTP）一可用就显示“已打开”；会话连上了但终端或文件没开，或没有连上，都说明“原因见会话底部”。
- 会话底部在终端已经能用、文件通道还在等的时候显示“终端已打开，正在打开文件通道…”，不再一直显示“正在连接”。

### 3. 账号下拉可维护，记住选择（“目标主机凭据”）

- 机器列表上方的“目标凭据”打开一个侧栏：新建、编辑、删除目标主机的用户名和密码（可起个名称）。密码只保存在系统凭据中，账户文件里只有名称和用户名。
- 每台机器的“账号”下拉里，除了门户给的账号（如 root），`$user` 账号展开成每个已保存的凭据（带钥匙图标，如“运维（root）”）和“$user（每次输入）”。选已保存的凭据打开时不再询问，按网页的做法把用户名和密码交给门户。
- 每台机器选过什么会被记住。已保存的凭据只用在选过它的机器上；没选过的机器默认用最近一次选的门户账号或“每次输入”（不会默认带上某个凭据的密码）。删除凭据时同时删除它的密码，选了它的机器改回默认。
- 在“堡垒机账户”里改了门户地址，旧门户各台机器的选择清掉（凭据保留）。
- 系统凭据里的密码找不到时（例如换了电脑），打开时照旧询问，并说明原因。

### 4. “关联已打开的文件会话”点了没反应（还有文件栏的“排序和显示”）

- **原因**：这两个菜单的选项是在菜单打开的那一刻才用代码填进去的。现在用的 Avalonia 12 不显示这时加进去的选项：菜单照样“打开”，但里面是空的，只有 2 个像素宽，在 Windows 上就是什么都没出现。文件栏的“排序和显示”菜单也一样（同样的写法）。
- **为什么测试一直没发现**：以前的测试只检查菜单“是打开的”、它的选项列表里有什么，没有检查菜单实际画出来了什么。本机所有测试（包括打开界面动画、模拟这台堡垒机的情况）都通过，真实窗口里却看不见。
- **怎么找到的**：在 Windows CI 的真实窗口里用真实鼠标去点，并比较点击前后按钮下方的屏幕：“快速命令”（普通弹出框）变化 2474 个点，“排序和显示”和“关联文件会话”都只有 8 个点，即没有打开。之后在本机看菜单实际画出的大小（2×32、没有选项），并用最小例子确认了 Avalonia 的这个行为。
- **修复**：菜单一开始就绑定一个列表，打开时只更新列表的内容（这样 Avalonia 会显示）。测试改为检查打开的菜单实际画出的选项和宽度；把修复改回去，这些测试会失败（已实测）。
- Windows CI 的真实窗口检查现在用屏幕判断三个菜单按钮是否真的打开，并用真实鼠标完成一次关联（选文件会话后，菜单里出现“解除关联”）。
- 程序里其他在打开时才填选项的地方（终端右键菜单的“快速命令”子菜单）是子菜单展开时才建立的，不受影响，已有测试覆盖。

### 5. 打包前独立审查发现并修复

- 正常关闭程序时不经过“注销门户”这一步（只有需要确认时才走），门户登录留在服务器上：现在有已登录的门户就先注销（最多等 3 秒，不询问）。
- 正在保存凭据或确认删除凭据时，在“堡垒机账户”里删除了这个堡垒机账户，账户会被写回来（而密码、密钥已经删了）：现在保持删除，刚写入的密码一并删除。
- 登录时正在确认证书，账户的门户地址被改了，旧门户的证书指纹会存到新地址上（下次误报“证书变了”）：现在只存给开始登录时的那个地址。
- 改了门户地址后，旧门户各台机器的选择还在：现在清掉。
- 已保存凭据会作为“最近一次选择”默认用到没选过它的机器上，双击一下就把这台机器的密码交给另一台：现在凭据只按机器记住。
- 关闭被取消后，堡垒机仍显示已登录但无法使用：现在会话改为未登录，可以重新登录。
- 其他：账户文件写入前检查不超过读取时的 4 MiB 上限；打开时用凭据当前的用户名和密码（中途被编辑过也一致）；只改了机器的选择时，“堡垒机账户”窗口不再刷新（已显示的动态口令不会被收起）；会话在终端出现前被关掉时，说“会话已关闭”。
- 审查还发现我加的 Windows 检查脚本里一个变量名覆盖了进程变量，会让整个真实窗口检查出错；已改正。

## 改动范围

- Studio：`ViewModels/BastionHubViewModel.cs`、`BastionLoginsViewModel.cs`、`Views/BastionHubView.axaml`（新）；`BastionAssetsViewModel`（机器的账号选项、记住选择、凭据）；`LibraryViewModel`/`LibraryView`（新标签）；`MainWindowViewModel`（标签、打开结果、关闭时注销）；`AccountStore`（`Logins`、`Choices`）；`AccountsViewModel`；`WorkspaceViewModel`（文件通道打开中的状态）；`WorkspaceView`（菜单项名称）。去掉 `Views/BastionAssetsWindow` 和 `IStudioInteraction.ShowBastion`。
- `WorkspaceView`：“关联文件会话”和“排序和显示”两个菜单的填法（`FilledAsItOpens`）。
- 测试：`BastionAssetsTests` 改为测标签，新增 7 项；`Alpha14Tests`（菜单实际画出的选项）；`LinkTests` 改为检查画出的菜单；`TestSupport` 的 `Menus`、测试用密钥库的 `OnWrite`；`ssh_fixture.py` 的 `FIXTURE_SFTP_SILENT`；Windows 真实窗口检查新增鼠标点击和按屏幕判断菜单是否打开。
- 版本 0.4.0-alpha.15；数据目录不变（账户文件多两个字段，旧版本读到会忽略）。

## 未验证 / 限制

- **在你的真实门户上只用过 alpha.13**：“堡垒机”标签、已保存凭据打开 `$user` 账号、“已打开”提前显示，都只对本地测试门户和测试服务器验证过。请实际用一次；已保存凭据第一次用时，留意门户是否接受。
- 已保存凭据只按机器记住：每台机器第一次要在下拉里选一次。
- 网页登录后在浏览器里做的密码策略检查本程序不做（同 alpha.13）。
- 文件通道在这台堡垒机的终端连接上仍要等到超时才结束（Core 和旧一代共用，没有改）；期间终端照常可用，文件请用 SFTP 会话或“关联文件会话”。
- 以下都没有运行过：Windows 10/11 桌面实机（CI 的 Windows 虚拟机用真实鼠标点过）、真实凭据库、真实的屏幕阅读器。
- 安装包没有数字签名。
