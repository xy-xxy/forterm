# Forterm Studio 重做计划（XTerminal 风格）

日期 2026-11-22。目标：在 `avalonia/` 内新建桌面工程，按 `资料/` 中 17 张 XTerminal 参考截图重做界面，功能与 alpha.36 对等；堡垒机通过 xshell/xftp 入口唤醒是首要保留能力。alpha.36 的 `Forterm.Desktop` 及更早版本冻结不动。

`资料/` 截图含真实内网/公网 IP 和主机名，仅作本地参考，不提交、不外传。

## 已确认的决定

| 事项 | 决定 |
|---|---|
| 技术栈 | C# + Avalonia；复用 `Forterm.Core`（协议层及测试），界面重做 |
| 首版范围 | 与 alpha.36 功能对等，分阶段交付 |
| 界面实现 | AXAML + MVVM（自带约 60 行的 `Mvvm/ObservableObject.cs`，不引入 CommunityToolkit 依赖），主题用资源字典，支持预设背景/主题色/界面缩放 |
| 素材 | 只复刻布局和交互；不用 XTerminal 名称、Logo、图标；图标用开源图标集 |
| 不做 | PRO 标记、广告、推广达人、AI 助手、云端仓库/账号/软件更新；RDP/VNC 暂缓 |
| 终端写入 | **按截图实现**：右键“执行 CD 命令到终端”、连接级“初始执行”“保活命令”、pwd 自动跳转（带“禁用 pwd 自动跳转”开关）。“初始执行”“保活命令”按连接配置，默认空。pwd 自动跳转对保存的 SSH 连接默认开启，与截图一致：截图里是“禁用”开关；可逐个连接禁用。唤醒的临时会话不自动写入任何内容（唯一例外是用户自己打开的“空闲保活”，见下）；在这类会话里手动“CD 到终端”或“新建终端到当前目录”前会先确认一次。含控制字符的路径一律不输入终端。 |
| 空闲保活 | 2026-11-24 用户要求：按“长时间没有键盘输入”自动发送一次输入，做成开关。默认关闭；打开后对所有 SSH / Telnet 会话生效，**包括控制器唤醒的会话**（这是唤醒会话“不自动写入任何内容”的唯一例外）；也可以只对某个会话开关 |
| 列表延迟/指标 | 延迟只测 TCP 握手耗时，不认证；CPU/内存/网速/磁盘只显示已打开会话的主机，不后台自动登录 |
| 打开方式 | 只用内置编辑器，不做外部编辑器（草稿不落本地磁盘的约定保持） |
| 入口等待 | 恢复 0.1.1 行为：xshell/xftp 入口等待主程序结束并转交退出码（C# Launcher 目前启动后立即返回 0，属退化） |

其余现有约定不变：不自动重连、不重放临时票据、3 秒 HMAC 去重、URL 只解码一次、参数不经 shell、秘密只进系统凭据库、安全保存（同目录临时文件+复核+改名）、FTP 无原子保证时拒绝覆盖。

## 架构

- 新工程 `avalonia/src/Forterm.Studio`（主程序），版本线 0.4.0-alpha.N，独立数据目录。
- Desktop 中与界面无关的仓库/偏好/导入导出移到共享库，新旧界面都引用。
- Launcher/Diagnose/Portable 入口改为指向新主程序。
- 测试：沿用 Core 协议测试；新增 ViewModel 单测、Headless UI 测试与截图对照。

## 阶段

1. **骨架与唤醒**：新工程、主题系统、主窗口框架；xshell 唤醒直达终端工作区、xftp 直达文件区；入口等待；端到端唤醒测试（去重、二次实例转交、xftp 的 SFTP/FTP 分流、诊断不连接）。
2. **连接库**：分组树、主机表（排序/搜索/多选批量/TCP 延迟）、六节连接编辑表单（代理、算法、编码、TERM、初始执行、保活命令、环境变量）、测试连接。
3. **三栏工作区**：页签/弹出/最大化/拖宽、终端、文件树、完整右键菜单、传输管理浮层、CD 到终端、新建终端到当前目录。
4. **监控**：全部区块与进程浮窗（结束需确认）；新增 `/proc/diskstats` 读写速率。
5. **编辑与文件进阶**：内置编辑器（现有安全保存）、权限、压缩、下载到桌面、pwd 联动。
6. **对等补齐**：FTP、Telnet、跳板链、agent、TOTP 账户、sudo 权限、隧道（端口转发）、系统配置全部分类。

每阶段：软件渲染截图与参考图并排对比；Mac 原生窗口运行；Windows 实机仍待现场（建议加 Windows CI）。
