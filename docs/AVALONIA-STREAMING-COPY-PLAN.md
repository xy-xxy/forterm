# 大文件复制对等收敛（alpha.8之后）

当前alpha.8全部复制16MiB内存是阶段限制，不能作为完整对等交付。经理确认旧Go只有同一FTP控制连接复制受16MiB限制；SFTP/独立跨源使用32KiB有界流式。

实现路径：

1. 每个SFTP来源独立资源标识；FTP兄弟视图共享物理控制连接资源标识。两端按稳定顺序预留，去重并逆序释放，不建立新认证连接。
2. 同一FTP控制连接复制保持明确16MiB缓冲限制；同资源移动优先已核对的改名，不把大文件移动误归入复制限制。
3. 其余SFTP/FTP独立来源打开已核对的源流、目标随机临时流，以32KiB缓冲读写，不整文件入RAM、不用本地明文中转。
4. 复用现有目标提交器的长度/SHA、目标临时内容校验、源关闭后完整SHA/身份复核、取消保旧和提交ACK不明处理。FTP源流关闭须显式消费完成ACK并释放其控制通道，再执行源复核。
5. 新增不可变目标计划（含来源ID、目录、原目标版本），SFTP已有目标需明确覆盖选择且服务端支持posix-rename；保留旧目标权限与现有双端复核。FTP不支持原子替换时拒绝，不能删除再改名。
6. 移动在目标提交确认后再复核并删除源；取消/源变化/源删除不明保留已提交副本并明确部分完成，不自动重试。
7. 测试实际大于16MiB的SFTP→SFTP、SFTP→FTP、FTP→SFTP、FTP独立连接→FTP；同一FTP连接大复制拒绝、同源大文件移动，以及有序预留的双向并行。核对双方认证计数，无额外登录。
8. 测试SFTP确认覆盖/拒绝/目标变化/保权限、取消保旧、源变化保留。软件渲染和源码/产物身份归档，真实GUI/Windows/生产仍待外部协调。

收敛后再移除矩阵中的当前阶段限制。权限递归/sudo、TOTP、布局快捷键与最终三包仍是后续工作，不能丢失。
