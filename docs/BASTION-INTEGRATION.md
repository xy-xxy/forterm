## 当前已经工作的链路

用户在堡垒机网页完成登录/MFA/审批，控制器按 Xshell/Xftp 格式启动 Forterm。`xshell.exe` / `xftp.exe` 把精确参数转交同目录 `forterm.exe`，客户端在内存中使用临时 SSH 凭据。用户已现场确认 SSH 与 SFTP 工作。

同一个已认证 SSH transport 按权限打开 shell、SFTP、exec 通道，用于终端、文件、在线编辑和监控，不因切换功能再次认证。某类通道拒绝时保留其他能力。外部重复调用有短时间去重；临时凭据不落库、不自动重用失效票据。

这条已工作的入口是兼容回退路径，接入新提供器不能破坏它。

## 现有历史接口能证明什么

据主聊天归纳，三个历史接口只能确认会话申请涉及 `sid` 和客户端选择。当前没有以下完整契约：

1. 用户身份登录、登录成功判定、MFA/验证码/SSO 的状态转换及注销。
2. 当前用户资产列表、分页/搜索、可用账号、协议及操作权限。
3. 会话申请、审批，以及 `sid` 如何兑换最终 SSH 代理端点和临时认证信息。

`sid` 的字段类型、有效期、用途及与客户端选择的关系仍需确认。不能把 sid 当密码、用户名或可直接传给 SSH 的地址；“有 sid”不等于票据签发或终端打开成功。

本轮没有读取这些历史接口的 Cookie/Token，也没有读取真实旧请求或发送生产请求。

无需索取或发送旧 Cookie、Token、密码、私钥、验证码、未脱敏 HAR 或真实一次性 URL。不在真实资产上“试探”路径；端点未确认的字段保持待填。

## 是否能去掉本机 SSO 工具

必须区分本机单点控制器与服务端 SSO：

- 若服务端提供受支持的独立登录、资产和会话票据接口，Forterm 可以在主进程实现完整链路，再直接进入现有 SSH 层。
- 若完整连接描述需要官方 SDK 的设备绑定/解密/签名，或服务端要求官方客户端参与，是否可去掉控制器取决于其受支持契约，不能先保证。
- 若官方仅允许系统浏览器授权，而用户要求完全在应用内登录，应明确交互差异后再选择方案；不能把打开外部网页标记成内置登录完成。

无论哪种方式，都不能省略服务端审批、MFA、权限校验或审计绑定。当前仍支持已有网页 + 控制器链路，尚未实现新的内置登录/资产列表。

## 可复用位置与需要新增的接线

以下现有位置已静态检查；新增路径只是建议，当前没有创建或接入运行时提供器。

| 位置 | 复用方式与边界 |
| --- | --- |
| `src/main/launch.ts` 的 `parseURL` | 若官方最终返回 SSH/SFTP URL，可在主进程复用严格解析与单次百分号解码；不从 sid 拼 URL |
| `src/main/schema.ts` 的 `connectionSchema` | 最终结构化连接描述必须校验。再做提供器约束及有效期检查；设 `temporary: true`，不保存为手动 Profile |
| `src/main/sessions.ts` 的 `Sessions.connect` | 复用 SSH、跳板、指纹与交互认证。返回 ID 仅代表创建连接任务；`openSSH` 是异步执行，不等于 SSH 已 ready |
| `src/main/sessions.ts` 的 `openTerminal` / `sftp` / `monitor` | 在同一 SSH transport 上复用通道。终端成功需看 `terminalStatus`；SFTP 就绪需看实际通道调用结果，不能只依赖 transport 的 `status: ready` |
| `src/main/prompts.ts` | 可复用排队、取消及秘密输入的呈现机制；门户挑战需独立类型/上下文与取消绑定，不与 SSH 认证回调混用 |
| `src/main/index.ts` 的 `owner` / `handle` | 扩展受限、校验后的门户操作 IPC；不提供 renderer 任意 HTTP 请求代理。现有窗口阻止导航，不可直接挪来承载登录重定向 |
| `src/shared/types.ts` / `src/preload/index.ts` | 将来增加“登录状态/资产查询/申请连接”的有限类型与事件；只返回操作引用、安全元数据及运行会话 ID，不返回原始 HTTP 响应或临时凭据 |
| `src/renderer/App.tsx` | 后续资产浏览与工作区接线；加载、失败、过期和审批中应有真实状态。不要创建静态假资产或未接通的成功按钮 |
| `src/main/launch-gate.ts` | 保留外部启动去重；内部点击使用独立在途操作去重与服务端约定，不能通过重复申请/兑换票据冒充重试 |
| `src/main/store.ts` | 现有手动连接库不用于存放门户会话或 SSH 票据。若保存门户地址或资产收藏，使用独立的非秘密配置/引用 |

建议新增的逻辑层：主进程 `bastion` 服务负责身份生命周期、资产引用、授权操作和票据交接；确认厂商后才实现相应 provider。renderer 的“连接资产”只传提供器/资产/账号引用，主进程独立申请并将完整凭据直接交给 `Sessions.connect`。

不得先把 `Connection`（含密码或一次性 URL）返回 renderer，再从前端调用现有手动 `connect` IPC；不为方便而让任意远程门户页拿到 `window.forterm`。

## 状态与成功门槛

| 阶段 | 可对用户陈述的事实 | 必须满足的门槛 |
| --- | --- | --- |
| 产品/契约未确认 | 待配置/暂不支持 | 不发猜测请求，不显示登录或连接成功 |
| 身份认证中/有挑战 | 正在登录/等待具体认证步骤 | 来自受支持的服务端状态，取消及过期可结束 |
| 身份已确认 | 已登录 | 有契约定义的身份确认，不能仅凭 HTTP 200、页面加载或有 Cookie |
| 资产读取 | 加载/空列表/错误 | 真实授权资产结果；分页尚未完成不伪装完整 |
| 会话授权/审批 | 正在申请/待审批/被拒绝 | 区分 pending、denied、expired、cancelled，不把 sid 当已获准 |
| 连接描述已签发 | 开始建立 SSH | 完整端点/认证/有效期符合契约，审批明确通过 |
| SSH 连接中 | 正在连接 | `Sessions.connect` ID 仅作跟踪 |
| 终端已打开 | 终端可用 | 真实 shell 通道 ready；SFTP/exec 不可用各自说明，保留可用通道 |

HTTP 成功、portal sid、Forterm 运行会话 ID、SSH transport ready 和 shell ready 是不同层次的结果，必须分别处理。

## 实现约束与验收计划

- 身份会话、Cookie/Token、一次性连接描述由主进程内存持有。登录窗口如需官方页面，使用独立隔离窗口/会话和明确允许的源，不带 Forterm preload/Node 权限；按官方重定向契约校验。真实服务使用有效 TLS/受信 CA，不全局关闭证书验证。
- 错误映射使用受控代码/静态消息，不将 HTTP body 或库异常塞进 toast/诊断。现有 IPC 的中文消息筛选不能代替提供器错误脱敏。
- 批准轮询和身份刷新仅按契约执行，有截止时间、取消和防重叠；SSH 临时票据不自动重放。兑换超时可能已消费，显示“结果未确认”，不盲目重试。
- 单次点击的在途操作防重入；只有服务端明确支持幂等键才使用其语义。注销、撤销和已开 SSH 的关系依契约明确，不能假定注销成功或永久保留授权。
- 拿到契约后先用本机合成 HTTP + SSH 服务验证：登录/MFA/取消/过期、资产分页与权限、审批拒绝/超时、票据缺字段/过期/一次消费、重复点击、注销，以及四能力与通道降级。
- 事件、日志、bootstrap、导出和诊断须断言不含 Cookie、Token、密码、票据或完整一次性 URL；认证与票据过期后保留可复制的编辑草稿，不自动重用旧票据。
- 只有完整链路及界面失败状态通过，再交付真正的内置接入版本；本轮文档更新不修改 0.1.4 源码行为，不重新打包，不宣称接入已完成。
