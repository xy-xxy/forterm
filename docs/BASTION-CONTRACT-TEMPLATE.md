# 堡垒机最小接口资料模板

用途：补齐“应用内登录 → 资产列表 → 授权/审批 → 最终 SSH 连接描述”。这是待填契约模板，不是可执行接口，不包含假定的 URL 或方法。

不要填旧 Cookie/Token、密码、验证码、私钥或真实一次性票据；所有秘密值用 `<已脱敏>`，资产和账号用合成标识。优先提供官方文档；没有文档时只记录你有权使用且允许记录的平台的一次新流程结构，优先测试环境。

## 先照这份清单记录一次正常流程

不需要安装抓包代理、MITM 或根证书。优先官方集成文档；没有文档时，在你有权使用的平台正常操作一次即可，不主动制造失败登录、不重复申请或审批。

1. 用 Chrome / Edge 打开登录页，在输入密码之前按 **F12 → Network（网络）**，勾选 **Preserve log（保留日志）**，选 **All（全部）**；确保左上角录制圆点开启。可先点清空，让这次流程容易识别。
2. 正常登录：输入账号/密码，按现有方式完成手机验证码、MFA、SSO 跳转。记录“首次提交 → 挑战 → 完成 → 身份成功”的顺序；不要把实际密码/验证码抄下来。
3. 打开资产页，正常搜索一个资产、翻到下一页，展开该资产并选择授权账号及 SSH 协议。若界面不提供分页或账号选择，注明“无此步骤”。
4. 点击一次 SSH / Xshell，按正常流程完成审批，直到真实终端启动。记录点击后的先后请求及成功界面，不重复提交同一审批。
5. 先看 **Fetch/XHR**，再回 **All** 看 **Doc**（登录跳转/表单）、**WS**（Messages）和本机工具请求。过滤 `localhost`、`127.0.0.1` 观察有无本地 HTTP / WebSocket；在 **Initiator** 看是哪段页面逻辑触发了请求或协议唤起。
6. 若只看到自定义协议唤起/工具启动，记录协议名、参数名称和发起顺序，值全部脱敏。浏览器 Network 看不到本机工具内部通信时直接说明“浏览器不可见”，不要靠重复执行、猜 URL、工具逆向或真实票据补齐。此时还需要受支持 SDK/控制器契约。

已知 `get_sso_cmd` / `set_double_approval_sid` / `get_operator_client_by_resource` 不用重新手抄。现在重点缺：**登录/MFA/身份确认、授权资产分页/搜索、资产账号/协议权限，以及 sid 之后最终 SSH 地址/端口/临时认证信息来自哪里。** 单有 sid 或选择 Xshell 的结果不能直接建立 SSH。

## 每个关键请求只给这些脱敏内容

在请求的 **Headers / Payload / Response / Initiator** 中逐项记录，优先贴下方表格或必要截图，不用先发整个 HAR。截图要同时遮住地址栏、请求URL、Header、Body、响应和浮层中的秘密。

| 内容 | 示例形式（全部合成） |
| --- | --- |
| 顺序及用途 | 01 登录提交 → 02 MFA → 03 身份确认 → 04 资产分页 → 05 资产账号 → 06 会话申请 → 07 批准 → 08 最终兑换 |
| 方法/路径/Content-Type | `POST /实际路径`、`application/json`（主机可换 `bastion.example`，路径字段名保留） |
| 请求字段及类型 | `username: string`、`password: string <已脱敏>`；必填/可选、query/form/JSON 放在哪里 |
| HTTP 与业务状态 | HTTP 200，`code: number`；成功、挑战、待审批等实际值/含义（只记录这次自然出现的状态） |
| 响应结构 | 保留字段名、类型、数组/对象层级、分页游标及账号/协议关系；秘密值替换为 `<已脱敏>` |
| 身份及授权载体 | Cookie / Header / body 的**名称**与生命周期，值不提供；审批和兑换使用哪个引用 |
| 关联 | 同一资产一直写 `ASSET_A`，同一账号 `ACCOUNT_A`，同一sid写 `SID_A`，游标写 `CURSOR_A`，不要每处随机改导致无法对照 |
| 来源与边界 | Initiator、页面跳转/本机HTTP/WS/自定义协议、是否官方要求控制器；过期/取消/幂等若有文档注明 |

可以附自然出现的错误/过期结构或官方文档，但不要求主动试错密码、锁账号、制造审批失败或重复消费票据。真实地址、个人信息、资产名和内部IP按需替换；字段结构及一致关联不要丢失。

## HAR 只在本机保留原件，脱敏版也要人工检查

Chrome 官方说明，**HAR (sanitized)** 默认移除 Cookie、Set-Cookie、Authorization 等敏感请求头。这不等于产品自己的字段、正文、URL/query 或 WS 消息都已清理，不能直接把该文件当作安全附件。

- 原始 HAR / 完整 cURL 只保留在你本机，不发到聊天。不需要启用 “with sensitive data”。
- 即使用 sanitized 导出，也要逐项查找并替换 `access_token`、`action_token`、`ssoPwd`、密码、OTP、Cookie值、Bearer值、sid/会话票据、私钥/验证器seed、URL query/fragment、请求及响应 body、重定向 Location、自定义Header、WS帧和协议唤起参数。不要删除字段名/类型；统一使用一致合成标识。
- 先提供几条关键请求的脱敏结构或截图清单；我们确认还缺哪一段，再定向补资料，无需一次上传所有流量。
- 浏览器内看不到最终兑换时如实说明，保留“仍依赖受支持的控制器/SDK”的边界；不发送真实手机验证器key或历史票据。

依据：[Chrome DevTools Network 官方参考：Preserve log / HAR导出](https://developer.chrome.com/docs/devtools/network/reference/#save-as-har)。上述产品字段清理清单是针对本任务的补充，官方 HAR 默认清理不能替代人工复核。

## 2. 三组完整契约

| 项目 | 登录 / 身份确认 | 资产 / 账号 / 权限 | 会话申请 / 审批 / sid 兑换 |
| --- | --- | --- | --- |
| HTTP 方法、路径、内容类型 | 待填 | 待填 | 待填；可能不止一步 |
| 请求字段名称、类型与必填性 | 待填，不含真实密码 | 待填 | 待填，明确资产/账号/协议引用 |
| 身份载体的名称及生存期 | 只填名称，值脱敏 | 说明如何携带身份 | 说明如何绑定授权 |
| 成功状态与响应结构 | 身份明确成功的判定 | 列表、稳定引用、分页、账号/协议授权 | pending/approved/denied 等具体结构 |
| 失败 / 过期 / 取消结构 | 待填 | 待填 | 待填，区分申请失败与已消费但响应未知 |
| MFA / 验证码 / SSO | 后续步骤与状态 | 如有二次验证请说明 | 审批/二次验证如何继续 |
| 最终结果 | 已登录的身份确认 | 可供申请的授权资产引用 | 完整 SSH URL 或结构化描述；或 SDK 转换规范 |

必须补齐最后一列中 **sid → 最终连接描述** 的所有步骤。仅提供“返回 sid、选择 Xshell 客户端”的接口仍不足以独立打开终端。

## 3. 连接描述的必要语义

根据真实契约说明字段映射，不猜字段名或秘密内容：

- SSH/SFTP 协议、代理地址、端口、认证方式及临时用户名/认证材料从何处获得。
- 是否已经批准、有效期起点/截止、一次性消费时点、连接与审计会话的绑定。
- 重复请求是否幂等，兑换响应超时是否允许重试，以及取消/撤销/注销行为。
- 主机指纹是否固定或经代理动态变化，支持哪些通道（shell/SFTP/exec）。

只给合成样例结构，真实主机和账号可用 `.example` 或测试标识代替。若这些值由工具解密/签名产生，提供官方契约，不提交可复用的真实工具票据。

## 4. 最小复核流程

1. 产品标识与文档确认同一版本，或管理员明确兼容范围。
2. 用脱敏结构检查身份成功、资产授权、审批/票据三段能否闭合；缺哪一步就标哪一步待补，不显示假成功。
3. 用合成回环服务实现并测试提供器，再进入经过授权的测试环境联调。

此模板不要求登录生产平台、抓取旧会话、提供未脱敏 HAR 或重放生产请求。
