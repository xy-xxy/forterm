# Forterm Studio 0.4.0-alpha.3 交付说明（2026-11-22）

阶段 3–6：三栏工作区、监控、编辑与文件进阶、对等补齐。计划和决定见 `docs/STUDIO-REBUILD-PLAN.md`，前两版见 `docs/STUDIO-ALPHA1-DELIVERY.md` 和 `docs/STUDIO-ALPHA2-DELIVERY.md`。alpha.36（`Forterm.Desktop`）及更早版本没有改动，也没有重新打包。

## 内容

### 阶段 3：工作区与文件

- **文件区**：
  - 操作：上传和下载（文件和文件夹）、新建文件和文件夹、重命名、复制路径、递归删除。
  - 删除前先做计划，上限 2000 项、32 层；链接只删除链接本身，不跟随；确认后才执行。执行时逐项按元数据核对，不读取文件内容（见下文审查部分）。
  - FTP 只删除文件和空目录，不做递归删除。
  - 所有操作进同一个串行队列。
  - 覆盖已有文件前要确认；新建文件用独占创建。
- **传输管理浮层**：
  - 显示进度、状态筛选和计数。
  - 支持取消；失败后停止剩余项目，不自动重试。
- **中央栏**：
  - 终端多页签，复用同一 SSH 连接。
  - “CD 到终端”和“在此新建终端”。
- **路径栏**：
  - 分段导航，也可以输入路径。
  - 服务器拒绝 REALPATH 时，可以手动输入绝对目录。

### 阶段 4：监控

- **Core 新增 `SharedSshSession.ExecAsync`**：使用独立 exec 通道，限制输出大小并设超时。
- **只读采集脚本固定**：os-release、时区、`/proc`、`df -T`、diskstats、网络、ps。
- **监控栏区块**：
  - 系统信息
  - CPU 逐核分段条和趋势
  - 内存环图
  - 网络趋势和流量
  - 磁盘：逐挂载读写和容量表
  - 热点进程
- **进程管理窗口**：
  - 搜索、排序、自动刷新。
  - 结束和强制结束都要确认，只允许 PID > 1。
- **刷新策略**：
  - 保存的连接默认每 3 秒自动刷新。
  - 控制器唤醒的会话默认手动刷新，因为每次 exec 都可能被堡垒机审计。

### 阶段 5：编辑与文件进阶

- **内置编辑器**（AvaloniaEdit）：
  - 支持不超过 1 MiB 的 UTF-8 文件，最多同时开 12 份。
  - 保留 BOM 和换行风格。
  - 保存需要确认，然后进入队列。
  - 没有原子替换能力时只允许“另存为”。
  - 来源关闭后变为只读；关闭页签或会话前会确认。
- **修改权限**：
  - 支持 rwx 和八进制，可以递归，可以单独指定文件权限。
  - 保留特殊位，不改所有者。
- **压缩**：在独立 exec 通道运行 tar，使用 noclobber，失败时只删除本次生成的归档。
- **下载到桌面**：不覆盖已有文件，同名时自动编号。
- **pwd 联动**：只给保存的 SSH 连接写入 OSC 7 提示符钩子，可以在连接设置中禁用；唤醒会话不写。

### 阶段 6：对等补齐（本版新增）

- **系统配置**（标题栏齿轮）：
  - 主题界面：20 个背景预设、10 个主题色、跟随系统、界面缩放 50–150%。
  - 通用终端：字号。
  - 本地终端：shell 路径。
  - 关于与验证说明。
  - 配置原子保存在数据目录的 `preferences.json`。
- **信息列**：
  - 连接列表的“信息”列只显示已打开会话的 CPU、内存、磁盘摘要，数据来自该会话的监控。
  - 未打开的连接不会被后台登录；会话关闭后清空。
- **堡垒机账户与动态验证码**（首页“堡垒机账户”）：
  - 账户信息：名称、门户地址（只允许 http/https，不能带账号密码）、用户名、备注。
  - 门户密码和 TOTP 密钥只保存在系统凭据库，`accounts.json` 里只有“已保存”标记。
  - 支持 Base32 密钥和 `otpauth://` URI，可选 6/8 位、5–300 秒周期（默认 30）、SHA1/256/512。
  - 验证码默认遮蔽。复制时按当前时间重新计算；周期结束后，如果剪贴板里仍是这个码，会自动清除。复制密码后 30 秒清除。
  - “打开门户”只调用系统浏览器。
  - 不实现门户登录和资产接口，等待厂商契约。
- **导入 alpha.36 配置**：
  - 首页“导入”可以识别 `Forterm.Avalonia.Profiles/1` 无秘密导出。
  - 单级 `JumpId` 展开为有序跳板链，第一跳在前。
  - 分组按名称合并或新建。
  - 文件中出现任何秘密字段（password/seed/privateKey/ticket 等）都会整份拒绝。
- **隧道**（首页“隧道”页签）：
  - 本地端口转发经由已保存的 SSH 连接，继承该连接的跳板链和代理。
  - 本地只监听 127.0.0.1。
  - 手动启动和停止，每条隧道使用独立的已认证连接。
  - 断开后显示原因，不自动重连。
  - 本地端口不能重复；删除经由的连接时一并删除它的隧道。
  - Core 新增 `SharedSshSession.ForwardLocal` / `LocalForward`（转发期间持有租约）。
- **sudo 修改权限**（与 alpha.36 对等）：
  - “修改权限”对 SFTP over SSH 提供“使用同一 SSH 连接的 sudo（root）”选项，复用 Core 的 `SudoPermissionService`。
  - 执行前先通过独立 exec 读取 device/inode 身份，核对与文件区看到的一致，并查询 sudo 策略；确认时要求明确认可“同一文件系统”。
  - 只有 sudo 输出本次随机提示后才询问密码；密码只写入这条命令的 stdin，不保存，不经过终端。
  - Core 新增只读属性 `SftpLease.SupportsSameSshExec`。
- **Windows CI**：新增 `.github/workflows/studio-windows.yml`。
  - 在 `windows-latest` 上运行 Studio 测试。
  - 发布四个入口，验证 `--runtime-check`、`xshell --diagnose` 退出码 0、`xftp` 非法参数退出码 2、`forterm-diagnose` 正常。

### 独立代码审查与修复

打包前，由另一个代理只读审查 Studio 代码，以及 Core 中本版新增的部分。共报告 16 项，下面逐项列出结论。

**高**

- **远程文件名直接拼成本机路径**。名为 `C:version.dll` 的远程文件在 Linux 上合法，Windows 却把它当作带盘符的路径，`Path.Combine` 会原样返回它。结果是“下载到桌面”或下载文件夹时，文件可能写到所选目录之外，例如程序目录。
  - 修复：新增 `FileActions.LocalName` / `LocalChild`，以下名称一律拒绝：
    - 带根或盘符的名称、含 `:` 的名称
    - Windows 非法字符、控制字符
    - `.`、`..`
    - 保留设备名（CON、COM1、LPT1 等）
    - 结尾带点或空格的名称
  - 此外，完整路径必须位于所选目录之内。文件夹下载在确认之前就计算并检查全部本机路径。
- **CD 到终端可被路径注入命令**。单引号已正确转义，但目录名中的 ^U、^C、ESC 等控制字符会被行编辑器执行。
  - 修复：路径含任何控制字符时，不向终端输入，只显示提示。

**中**

- **控制器唤醒的会话也会被输入 cd**。
  - 修复：在临时会话里手动“CD 到终端”或“新建终端到当前目录”时，先说明情况并确认，每个会话只问一次。
- **一个唤醒卡住会挡住后面所有唤醒**。唤醒队列逐个等待，前一个在等密码或指纹确认时，后面已确认收到的唤醒都打不开。
  - 修复：每个唤醒独立运行；单个唤醒出错只在窗口提示，不影响后续唤醒。
- **关闭窗口不提醒**。关窗口会直接丢弃未保存草稿，并中断正在进行的传输。
  - 修复：关闭窗口前确认三类内容：未保存草稿、排队或进行中的传输、运行中的隧道。之后取消传输并最多等 5 秒，让传输清理临时项。关闭单个会话页签也会确认进行中的传输。
- **删除不核对已确认的内容**。之前提示说“删除前核对原版本”，实际并不核对。串行队列可能在确认很久之后才执行，期间被替换的文件也会被删除。
  - 修复：执行前逐项核对类型（不跟随链接）和普通文件大小，不一致就停止。提示文字也改为与实际行为一致。
  - 限制：目录列表不含修改时间，所以同样大小的替换无法发现。
- **导入会带入自动执行的命令**。导入文件里的“初始执行/保活命令”会在首次连接时自动输入终端。
  - 修复：导入时清空这两项，并提示用户自行填写。代理和默认路径照常导入；首次连接仍需确认主机指纹。

**低**

- **结束进程可能误杀**。PID 被复用后，结束的会是另一个进程。
  - 修复：发送信号的同一条 exec 先核对进程启动时间（`ps -o lstart`），不一致就不发送。
- **连接完成时窗口已关闭，会话泄漏**。
  - 修复：SSH、SFTP、FTP、Telnet、隧道等连接结果返回时，如果工作区或窗口已关闭，立即释放。
- **pwd 联动会改变右键菜单的操作对象**。
  - 修复：文件树右键菜单打开期间，pwd 联动暂缓，菜单关闭后再跳转。
- **文件夹下载会合并进已存在的目录**。两个同名下载排队时，后一个会写进前一个创建的目录。
  - 修复：执行时目录已存在就停止，不合并。
- **资源泄漏**。
  - 修复：关闭的窗口不再监听共享连接库，也不再测延迟；监控循环的取消源会释放；账户窗口关闭后，正在读取的 TOTP 密钥会被丢弃，替换时清零旧密钥。
- **新终端页签可能一直空白**。另一个终端正在打开时，点“+”得到的页签接不上终端。
  - 修复：每个页签独立打开终端。
- **初始执行可能被丢弃**。连接前关掉初始的空页签，之后打开的终端就不再执行“初始执行”。
  - 修复：只有真正接收过初始执行的页签关闭时，才停止初始执行和保活命令。
- **连接库或账户文件中的 `null` 字段导致启动崩溃**。
  - 修复：这类文件按“文件无法读取”处理：本次使用临时空库并提示，原文件不改动。偏好文件无法读取时使用默认值。

**按产品决定保留**

- pwd 联动对保存的 SSH 连接默认开启，与截图中的“禁用 pwd 自动跳转”开关一致。
  - 审查指出，如果保存的连接指向堡垒机菜单或网络设备 CLI，钩子命令会被输入到这些界面。这类连接请在“其他设置”里禁用 pwd 联动。
  - 是否改为默认关闭，留给使用者决定。
- `-newwin` 启动不参与 3 秒去重（Core 中 alpha.36 的既有行为，`-newwin` 明确要求新窗口），本版不改。

### 第二轮审查（复查上述修复）

另一个代理复查了修复后的代码，报告 11 项。逐项核实后全部修复。其中两项高优先级问题在阶段 3 就已存在，第一轮没有发现：

**高**

- **删除会完整读取文件内容**。删除沿用了 alpha.36 单项删除的“内容哈希核对”，每个文件要完整读两遍。后果有三：
  - 删除大目录会超时，且超时时已经删掉一部分。
  - 能删除但不可读的文件删不掉。
  - 删除一个 10GB 文件等于下载 20GB。
  
  修复：Core 新增 `RemoteFileOperations.RemoveNodeByMetadataAsync`，SFTP 和 FTP 各一份实现，只新增、不改变已有行为。它按元数据核对：先逐级复核父目录（不允许任何一级是链接），再用 lstat 核对类型、是否链接、普通文件大小与确认时一致，然后删除。全程不读文件内容。去掉两分钟总时限，每个元数据请求仍有各自的超时，任务可以随时取消。
- **删除链接必然失败**。Core 的节点捕获拒绝链接，所以对话框写着“只删除链接本身”，实际却删不了。递归删除遇到第一个链接就停，此时前面的内容已经删掉。
  - 修复：SFTP 删除链接本身，不跟随。FTP 遇到链接时在确认之前就拒绝，不做任何修改。确认文字会写明链接和特殊项的数量。

**中**

- 选择盘符根目录（如 `D:\`）作为下载目标时，所有子路径都被误判为“越出所选目录”。已修复。
- 文件夹上传、下载和递归删除中，“结果未确认”被报告成“失败”，用户取消也被报告成“失败”。现在保留为“需核对”和“已取消”。

**低**

- Telnet 连接期间关掉初始页签，连接会接到已关闭的页签上，造成泄漏。现在改为新开一个页签。已关闭的页签不再申请 shell 通道。
- 关闭窗口时，确认对话框打开期间再次关闭会弹出第二个确认，期间到达的唤醒也会被送进这个正在关闭的窗口。现在有进行中标记，唤醒改投其他窗口或新窗口。
- 编辑运行中的隧道时，如果新配置被拒（例如端口重复），隧道已经先被停掉。现在先校验、后停止。窗口关闭会取消正在进行的隧道连接。
- 损坏的连接库或导入文件中，标识为空、重复或上级缺失时，会显示英文 .NET 异常。现在统一报告为“文件无效”。
- 已保存的 TOTP 密钥格式错误时没有任何提示。现在会显示错误。
- 工作区关闭后，保活命令循环会抛出未观察的异常。已修复。

### 第三轮审查（只审新的删除路径）

删除属于破坏性操作，又刚刚重写过，所以针对它单独再审一轮。报告 1 高、2 中、4 低，逐项核实：

**高**

- **SFTP 文件通道可能被误关**。SFTP 保活探测的是“最近核对过的目录”。递归删除先核对深层目录，随后又把它删掉，下一次 15 秒保活就会因目录不存在而关闭文件通道，删除任务被显示为“已取消”。
  - 修复：Core 的元数据删除在核对父目录后，把保活探测目录设为这个父目录（它不会被本次删除）。

**中**

- **目录被替换后，删除会落到替换品里**。之前只核对目录的所有者、组和权限，所以确认后目录被换成一个同所有者、同权限的“替身”，删除会落到替身里。
  - 修复：规划时记录每个目录的快照和修改时间。执行时，每个目录在第一次被用作父目录时，修改时间必须与规划时一致：在此之前没有从它里面删过任何东西，所以修改时间不一致就说明目录被替换，或者其中有增减。不一致即停止。
  - 测试 `RecursiveDeleteStopsWhenADirectoryWasReplacedAfterConfirmation` 在确认后立刻替换目录，结果是 0 项被删除。
  - FTP 目录没有修改时间可比，见下一条。
- **FTP 递归删除可能跟随链接**。DOS/IIS 格式或隐藏符号链接的服务器上，链接会显示成目录。另外，元数据请求的 8 秒时限覆盖了等待和多次列表，超时会被报成“已取消”。
  - 修复：FTP 只删除文件和**空目录**，不做递归删除，在确认之前就拒绝。超时等非用户取消的情况统一报为失败。

**低**

- **类型变化漏检**。FIFO 或套接字被换成普通文件时没有发现。现在同时核对“是否普通文件”。
- **单独删除 FIFO 或套接字总是失败**。现在节点会记录自己是否为普通文件，可以正常删除。
- **核对与删除之间的残余竞争窗口**：核对父目录、lstat、删除三步在服务器上分别解析路径，中间有一到两次往返的窗口。SFTP v3 无法原子地解决这个问题，记为已知限制。

测试夹具新增 `FIXTURE_LSTAT_LIST=1`，开启后目录列表与 OpenSSH 一样描述链接本身。默认行为不变，旧测试不受影响。

新增 `ReviewFixTests`，共 23 个用例，覆盖三轮修复。其中链接删除测试在被删目录里放了一个 4MiB 文件，并断言删除过程中没有打开任何文件。另外，监控测试增加了 PID 复用场景，导入测试增加了命令被清空的场景。

## 验证

全部在 macOS arm64 上运行，环境变量 `TMPDIR=$(getconf DARWIN_USER_TEMP_DIR)`。

- **Studio 测试**：`Forterm.Studio.Tests` 最终版本 **88 项全部通过，连续运行两次**。
  - 第三轮修复之前，也有多次全量通过：65 项（两次）、83 项（两次）、86 项（两次）。
  - 本轮没有出现失败的全量运行。开发过程中出现过个别失败，都在提交前修复，具体是：

## 未验证 / 限制

- 以下都没有运行过：
  - Windows 实机、ConPTY、DPI、输入法
  - 真实控制器唤醒、真实堡垒机
  - Windows 凭据管理器的读写
  - Mac 钥匙串的真实读写：测试中用内存替身。
- Windows CI 工作流已编写，但仓库还没有提交和推送，**没有在 GitHub 上运行过**；第一次运行可能暴露平台差异。
- 截图都是 Avalonia Headless + Skia 软件渲染，不等于原生窗口验证。
- sudo 修改权限依赖服务器的 `/usr/bin/python3` 和 sudo 策略。要求 TTY 的 sudo 策略会被拒绝，不会降级到在终端里输入。只在回环夹具上验证过，没有在真实服务器上验证。
- 删除的核对范围：
  - 按元数据核对，不比较文件内容。普通文件被同样大小的内容替换，或者在确认与执行之间被改写，都发现不了。
  - SFTP 的核对与删除之间仍有一到两次往返的竞争窗口（协议限制）。
  - FTP 不做递归删除。
- 关闭窗口时的确认，只在视图模型层测试过：已覆盖确认对话框和取消传输；`Closing` 事件中的取消与再次关闭没有自动化测试。
- pwd 联动对保存的 SSH 连接默认开启。保存的连接如果指向堡垒机菜单、网络设备或非 bash/zsh 的 shell，请在连接的“其他设置”里禁用它，否则提示符钩子会被输入到这些界面。
- 隧道：
  - 只做本地转发，不做远程转发和动态（SOCKS）转发。
  - 运行中的隧道不会持久化，程序退出后需要手动重新启动。
- 没有实现：
  - X11 转发（SSH.NET 不支持）
  - 会话环境变量
  - 主机密钥、加密、密钥交换算法偏好
  - RDP/VNC（按计划暂缓）
- 主题预设的颜色是 Studio 自己的近似值，没有使用 XTerminal 的素材。
- 本机环境存在接管 TCP 握手的代理或 VPN 时，文档保留地址也会显示约 1–20 ms 延迟。这是只测 TCP 握手的固有局限。
