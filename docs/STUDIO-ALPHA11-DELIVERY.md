# Forterm Studio 0.4.0-alpha.11 交付说明（2026-11-27）

本版做的是 alpha.10 交付后列出的“还可以做的”（用户 11-27：“把还可以做的一起做完”）：参考截图里的“全局透明度（Beta）”，以及 alpha.10 留下的几处限制。系统文件选择框在锁屏时盖不住，是系统的限制，本版没有再改（锁定之后它返回的结果照旧不用）。计划和决定见 `docs/STUDIO-REBUILD-PLAN.md`，上一版见 `docs/STUDIO-ALPHA10-DELIVERY.md`。

Core 和 vendor 的 SSH 库有改动，`Forterm.Desktop` 的行为不变（见“改动范围”）。`Forterm.Desktop` 的源码、alpha.10 及更早的包、预览包和检查点都没有改动。

## 内容

### 全局透明度（Beta）（系统配置 → 主题界面）

- 开启后，主窗口的底色变透明：各栏、标题栏和终端后面能看到桌面和其他窗口，程度用“透出”（10%–90%）调节。文字、对话框、菜单、输入框和锁屏不透明。
- “毛玻璃”：透出的部分模糊显示，文字更容易看清（Windows 10/11、macOS 支持时；不支持时是纯透明）。
- 不与背景图片一起生效：有背景图片时显示图片，设置页上会说明。系统不支持透明窗口时，看起来和不开一样。
- 可以和“全局不透明度”一起用。“恢复默认外观”现在也会恢复不透明度、透明度和透出程度（背景图片本身仍用它自己的“移除”）。
- 参考截图里说开启后“顶部窗口将无法双击，系统自动调整布局将无法使用”，那是它自己的实现方式的限制。本版的透明窗口只改窗口底色，不改标题栏和窗口按钮的处理；但开启时标题栏双击和贴靠布局都没有专门验证过。

**顺带修正 alpha.10 的问题**：设了背景图片时，半透明的颜色是改在整个程序上的，设置窗口和对话框的底色也跟着变成半透明，画在白色上，深色主题下会发灰。现在半透明只用在主窗口自己身上，其他窗口保持不透明。

### 锁定期间的连接问题不再超时

- 锁定期间唤醒的会话，如果要确认主机指纹或回答登录问题（例如堡垒机的动态口令），对话框在锁屏下面等着。以前我们自己的等待上限（连接超时，默认 45 秒）一到就失败；现在回答问题的时间不计入连接超时。
- 锁屏上会写“有 N 个问题在等你回答（主机指纹、登录或 sudo 密码），解锁后回答”，并说明哪些时限仍然有效；主窗口和问题对话框自己的锁屏上都有。
- **服务器自己的登录时限仍然有效**：OpenSSH 默认 120 秒，堡垒机可能更短；超过了服务器会断开，需要从控制器重新发起。这一点我们改不了。
- 不是在锁定期间也一样：回答问题时不再被我们的超时打断。网络或服务器不响应的时间照常计时（有测试：服务器报了版本之后一言不发，仍按超时放弃）。

### 停止粘贴不会切断字符

- 粘贴现在按不超过 1 KiB 的小段发出，每段都是完整的字符，一段开始发了就整段发完。停止只在两段之间生效，所以服务器不会收到半个字符，无论终端用什么编码（UTF-8、GBK 等）。
- 停止后，正在发的那一小段（括号粘贴时还有结束标记）仍要等服务器收下。提示条不再立即消失，而是写“正在停止粘贴：正在发的一小段和结束标记等服务器收下，之后的不再发送”（不是括号粘贴时不提结束标记，没有按钮），发完后消失，状态栏说明“已停止粘贴……（已补上结束标记）”。如果停止时已经在发最后一段，其实没有什么可停的，状态栏说“粘贴已全部发出：停止时已经在发最后一段”。服务器一直不收时它们发不出去，这是协议决定的；在那之前打的字排在它们后面，顺序不乱。

### 关闭保护对每个窗口都有效

- 以前只保护“用户最后操作的那个窗口”。现在，哪个窗口里有页签或栏消失了，就保护哪个窗口的 ×，不管用户当时在哪个窗口里（例如在设置窗口里时，主窗口的一个页签消失）。

## 独立代码审查

打包前做了一轮独立审查（11-27，审查者在仓库的副本里写测试实测）：没有高危，1 项中危、4 项低危，另有几处措辞，全部修改，并为每项加了测试或改了测试。

| 等级 | 问题 | 处理 |
|---|---|---|
| 中 | 锁定期间，问题对话框被放弃（会话关掉、服务器断开）而关闭时，它的锁屏一直挂在全局的“等待中的问题”通知上，对话框和它的内容（主机和指纹）在程序退出前都不会释放；主窗口在锁定时被程序关闭也一样 | 窗口关闭时放开它的锁屏；测试数订阅者 |
| 低 | 服务器卡住时停止一次小粘贴（只有一段）：其实什么都没停，整段都发出了，状态栏却一直写“正在停止粘贴” | 这种情况说明“粘贴已全部发出：停止时已经在发最后一段” |
| 低 | 停止后的提示条总说“……和结束标记等服务器收下”，没有括号粘贴时并没有结束标记 | 按实际情况说 |
| 低 | 锁屏上“等待不计入连接超时”对 sudo 密码（有自己的时限）和启动隧道（2 分钟）不成立 | 锁屏如实列出这些时限 |
| 低 | 在设置里搜索“透明度”“毛玻璃”时只显示透明窗口的卡片，调节程度的“透出”滑块在背景图片卡片里，搜不出来 | 透明窗口卡片有自己的“透出”滑块（和图片共用一个值） |

措辞：“系统不支持时看起来和不开一样”改为“看不到后面的内容，各栏颜色会稍有变化”（不支持时半透明的各栏叠在不透明底色上，颜色会略有不同）；有背景图片时的提示“窗口不透明”改为“看不到后面的桌面”（不透明度小于 100% 时窗口仍是半透明的）。

审查者确认没有问题的部分：回答计时的暂停和恢复（嵌套的问题、已取消或已释放的计时器、服务器先断开时）、主机指纹和登录问题两条路径都被覆盖、SSH 库补丁只在设置了选项时生效、补丁记录可以还原并逐字重新生成、`Forterm.Desktop` 不受影响（45 秒下限与原来的常数相同，没有设置选项时走原来的路径）；粘贴的分段（成对代理字符、孤立代理字符）、停止只在两段之间、锁的顺序不会死锁、转码层总是收到完整字符；半透明只在主窗口、明暗切换跟随、其他窗口和对话框不透明；关闭保护的每个调用都改成了按窗口；锁屏的等待说明只有数量，不含主机。

**审查过程中的一次事故**：审查者第一次复制仓库时，把 `avalonia/artifacts`（35 GB 的旧构建产物）也复制进了临时目录，磁盘满了大约一分钟，随后它删掉了这份复制。仓库本身、发布包和检查点都没有改动（alpha.10 两个包的 SHA256 复核一致）。那段时间我正在跑全量测试，Studio 测试里有 1 项因为测试服务器进程退出而失败（见“验证”），应当就是这个原因。

## 改动范围

- Studio（`avalonia/src/Forterm.Studio`）：主窗口外观（`MainWindow` 的 `Look`，`Appearance.SeeThroughBrushes`、`IsClear`），设置页“全局透明度（Beta）”卡片，锁屏的等待说明（`AppLock.Questions`、`LockView`），对话框计数（`DialogInteraction`），粘贴（`IdleWatch.SendPasteAsync`、`PieceLength`，`TerminalTabViewModel.IsPasteStopping`，提示条），关闭保护（`IStudioInteraction.Moved`、`CloseGuard.MovedIn`）。
- Core（与 `Forterm.Desktop` 共用，只增不改）：`SessionConnectOptions.AnswersUntimed`（默认关），`SharedSshSession` 只在它打开时暂停计时。`Forterm.Desktop` 不打开它，行为不变。
- vendor SSH 库（`SSH.NET`）：`ConnectionInfo.Answering`（默认为空），`Session.WaitOnHandle` 只在它不为空时按 100 毫秒一段等待、不计回答的时间；为空时和以前完全一样。补丁记录 `vendor/patches/sshnet-shared-transport.patch` 的这两个文件按原记录还原出上游后重新生成，并核对过重新应用后与现在的文件一致。客户端标识没有改。
- 工具和 CI：`native-check.py --clear`（新），CI 加一步。
- 版本 0.4.0-alpha.11；数据目录不变。
- **退回 alpha.10**：alpha.10 能读取设置文件，但一旦保存会丢掉“全局透明度”和“毛玻璃”两项。

## 未验证 / 限制

- **真实堡垒机“登录后断开”的原因仍未确定**，还在等 alpha.9 之后任一版本的“复制连接诊断”。
- 以下都没有运行过：Windows 10/11 桌面实机（安装包的 SmartScreen 和杀毒软件、ConPTY、DPI、输入法、AltGr、真实拖放、透明窗口和毛玻璃的实际效果）；真实控制器唤醒；Windows 凭据管理器和 Mac 钥匙串的真实读写（锁屏密码存在这里）；真实的屏幕阅读器。
- 全局透明度：毛玻璃在 CI 的 Windows 虚拟机上画成不透明，在 Windows 10/11 实机和 macOS 上的实际效果没有看过（关闭了系统“透明效果”的电脑上也会是不透明的，此时可以关掉毛玻璃用纯透明）；纯透明在 Windows CI 截图和 macOS 窗口截图里都确认生效；开启时的标题栏双击和贴靠布局没有验证。透出 50% 时，叠在窗口底色上的栏实际约透出 25%，背景图片也是这样叠的。
- 锁定期间的问题：我们自己不再计时，但服务器自己的登录时限（OpenSSH 默认 120 秒，堡垒机可能更短）、启动隧道的 2 分钟和 sudo 的时限仍然有效；超过后需要从控制器重新发起。
- 粘贴：服务器一直不接收时，停止后正在发的那一小段（不超过 1 KiB）和结束标记发不出去，之后打的字排在它们后面，这是协议决定的。
- 系统文件选择框在锁屏时仍然盖不住（锁定之后它返回的结果不用）。
- 安装包没有数字签名。
- 其他限制见 `docs/STUDIO-ALPHA4-DELIVERY.md` 到 `docs/STUDIO-ALPHA10-DELIVERY.md`。
