# Forterm Studio 0.4.0-alpha.13 交付说明（2026-11-27）

本版做“堡垒机账户”的免浏览器登录：用户 11-27 要求不进浏览器就能登录堡垒机、连接 SSH 和 SFTP。按用户在浏览器里录下的登录和连接过程（HAR，只经本机工具脱敏后阅读）以及堡垒机厂商的单点登录客户端实现。计划和决定见 `docs/STUDIO-REBUILD-PLAN.md`，上一版见 `docs/STUDIO-ALPHA12-DELIVERY.md`。

Core、vendor 没有改动，`Forterm.Desktop` 不受影响。

## 内容

### 1. 登录堡垒机（不进浏览器）

- **适用的门户**：录制里的这一种（深信服风格的“fort”门户，登录方式“用户名+密码+手机APP动态口令”）。别的门户、别的登录方式本版不支持，会如实说明可用的方式。
- **账户**：堡垒机账户多了“租户”一项（登录页上的“租户名称”）。门户地址是 `https://` 并填了租户的账户，详情里有“登录堡垒机”按钮，打开“堡垒机资产”窗口并立即登录。
- **登录**：用户名；密码取自系统凭据（没保存就当场问，不保存）；动态口令由保存的验证器密钥算出（没保存就当场问，而且和网页一样，在确认证书、门户准备好接收口令之后才问，不会因为核对指纹而过期）。密码按网页的做法以 SM3 摘要发送，口令按网页的编码发送；每个请求带网页脚本的 `rd1`/`rd2` 校验参数和门户发的令牌。
- **网页会停下的地方这里也停下**，并说明原因：租户名不对、口令或密码错误、要求先修改密码（首次登录、过期、初始化用户、不符合密码策略）、门户给出的登录限制说明、这个账号在别处还有登录会话（网页上会弹出“用户会话信息”，本程序不代为处理）。门户已经让登录进来、但本程序不继续时，会立即注销这次登录。
- **证书**：第一次连接时，什么都不发送，先显示门户证书的 SHA-256 指纹、签发对象和有效期，请和管理员给的指纹核对；信任后指纹保存在账户里（只存指纹）。以后证书变了，说明“可能有人在冒充堡垒机”并拒绝，除非再次确认。改了账户的门户地址，已信任的指纹作废。
- **资产**：按名称或地址搜索，每页 20 台，可翻页；每台资产可选账号，点“SSH”或“SFTP”。同一时间只做一件事：打开会话、翻页、登录时按钮暂时不可用，失败时窗口底部说明门户的原因。
- **打开会话**：向门户要一次性会话编号并登记（和网页一样），然后按厂商客户端启动 Xshell / Xftp 的方式，在 Forterm 里打开：`ssh://<会话编号>:''@<门户主机>:<SSH 端口>`（密码就是两个单引号），走和控制器唤醒完全相同的路径。所以它是一次性的：断开后不会自动重连，也不会再用这个编号；要再连就再点一次。
- **`$user` 账号**（目标主机的账号由用户自己填）：打开时问目标主机的账号和密码，按网页的做法交给门户，不保存。
- **其他账号**：和网页一样先问门户这个账号是否需要填写密码；需要时问它的密码，不需要时按网页的实际做法发送（网页在这种情况下发出的账号和密码字段是字面的 `undefined`，本程序照样发送）。
- 登录状态只在内存里；关闭窗口或“退出登录”会向门户注销，关闭时还在登录也一样（已发出的登录请求会等到回应，确认登录进来了就注销）。门户的令牌、密码和口令不写入磁盘、状态栏或连接诊断；会话编号和控制器唤醒时一样作为这次 SSH 的用户名，连接诊断里只写它的长度和类型；验证器密钥用完即从内存清除。

### 2. 连接诊断：“唤醒参数”

- 控制器唤醒的会话，连接诊断多一行，说明控制器怎样填用户名和密码，不写出它们：用户名长度和类型（标识 / 数字 / 字母和数字 / 含符号），密码与用户名相同、为空、不同（及长度；不写密码由哪类字符组成）。用来对照堡垒机客户端拼出的地址格式。

### 3. 打包前独立审查发现并修复

审查对照了录制摘要和门户自己的脚本（`login.js`、`sso-list.js`、`myajax.js`），并在副本里写了探测测试。

- **点“SSH”/“SFTP”失败时窗口什么都不说**（门户拒绝、要求重新登录、证书变了等都被吞掉，状态停在“正在打开…”）：现在显示门户的原因。
- **连续点两台资产会互相干扰**：门户每登记一个会话就换一个操作令牌，两个同时进行时后一个用了旧令牌，只打开了一个，另一个的编号发出了却没登记。现在门户的调用一次只进行一个，窗口忙时按钮不可用、再点不发送。
- **同一窗口退出后再登录，又要求确认证书**（刚信任的指纹没有被读回）：现在每次登录读账户当前保存的指纹。
- 对照录制和脚本后改正的地方：
  - 登录后多发了一个录制里没有的 `search_login`，已去掉。
  - 网页在登录结果里会停下的几种情况（`fortAdminIp` 的说明、`isWarn` 的“用户会话信息”）原来没处理，现在按网页的顺序处理，停下时注销。
  - 动态口令原来在确认证书之前就问，核对指纹期间可能过期；现在在门户准备好之后才问。
  - 普通账号原来不问门户是否需要密码，而且发的是空值；现在和网页一样先问 `is_no_pass`，不需要时发字面的 `undefined`。
  - 会话编号除了带横线的格式，也接受 32 位不带横线的十六进制（录制只说明是 32～36 位十六进制和横线）。
  - 窗口在登录中途关闭，原来可能留下一个没有注销的登录。
  - 连接诊断里的“唤醒参数”原来会写出密码由哪类字符组成，已去掉。
- 审查怀疑 `access_token` 请求头没有依据：用现在的脱敏工具重新生成录制摘要后确认，网页的每个请求都带这个头（只看了名字），所以保持不变。

### 4. HAR 脱敏工具

- 字段名、参数名不再被误当成主机名替换掉；Cookie 名里像编号的部分替换掉；列出返回头里带 token 的名字（只列名字）。

## 未验证 / 限制

- **没有连过你的真实门户**：只对按录制做的本地测试门户验证过。测试门户是照录制写的，录制里没有出现的情况（例如需要审批的资产、门户要求的其他检查）不知道门户会怎样回应。请实际登录一次，失败时把窗口底部的说明发给我。
- 录制里只有 `$user` 账号的打开过程。“先问门户是否需要密码”和“发送 `undefined`”是照网页脚本做的，没有在录制里出现过。
- 网页登录后在浏览器里还会按密码策略检查一遍密码（长度、字符种类等），不符合时要求改密码；本程序不做这一步。你的密码在网页上能直接登录，就没有影响。
- 退出后 30 秒内再次登录，验证器算出的口令可能和上次相同，门户如果不接受重复的口令，等下一个口令再试。
- 只支持“用户名+密码+手机APP动态口令”登录，只打开 SSH 和 SFTP（门户上的 RDP 等协议不支持）。
- “堡垒机资产”窗口只在测试里以软件渲染画过，没有在真实窗口里打开过。
- 以下都没有运行过：Windows 10/11 桌面实机、真实凭据库、真实的屏幕阅读器（同 alpha.12）。
- 安装包没有数字签名。
