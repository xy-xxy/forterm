# Forterm 0.1.4

2026-10-26 · Windows 10/11 x64

修复 0.1.3 在最小窗口和高缩放下，侧栏外框正常但实际功能按钮越界的问题。

- 顶部导航与底部主题栏固定保留，连接列表和工具区各自滚动；低高度缩小装饰间距。导入、导出、心跳设置等可用滚轮和键盘到达。
- 窄窗口的布局工具栏内部横向滚动，保留分屏选择、方向、重置及面板开关的访问路径。
- 欢迎页和纯 SFTP 工作区内部滚动，使初始连接入口、文件工具和目录操作在高缩放下仍可访问。
- 重新限制编辑器与上方工作区的高度预算、文件/监控比例；最小分区需容纳完整控件，不再只保证容器高度大于零。
- 长传输队列限制在视口高度的 20% 内并独立滚动，避免高缩放时挤掉工作区；六条上传记录展开时验证刷新与在线保存仍可操作。
- 保留五类拖动、键盘调整、尺寸持久化、未保存草稿保护、同一 SSH 会话四种能力与现有堡垒机入口。

本轮新增控件级回归：1050×650 原生窗口，125% / 150% 缩放，空列表和 40 多条连接、窗口恢复。99 次实际控件检查验证视口、所有裁切祖先、中心命中，禁止通过程序滚动隐藏的根容器掩盖问题；鼠标和键盘触发临时 JSON 导入/导出、主题、帮助、设置、在线保存与监控。实际拖动与统一工作区回归也通过。

详细证据见 `VALIDATION-0.1.4.md` 和 `reachability-0.1.4.json`。本轮不重复运行未变更的协议测试。Windows 包在 macOS 交叉构建；Windows 原生显示缩放、鼠标/键盘、ConPTY 及生产堡垒机仍需现场验收。没有推送或上传发布，0.1.3 包保留。

升级：退出旧版，将 ZIP 解压到独立目录，将控制器路径改为新版 `xshell.exe` / `xftp.exe`。四入口需要与完整共享运行时保持同目录。堡垒机内置登录与资产接入仍等待厂商/版本及接口信息；现有控制器接入保持。
