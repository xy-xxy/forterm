## 更正：此前的设置页说明与实际不符

alpha.3 到 alpha.5 的设置页“会话保护”里写着“剪贴板粘贴多行前先预览确认”，**但 Studio 一直没有实现**：粘贴（包括在终端里点右键）会直接发送，多行内容会立即执行。本版实现了它，并把说明改成实际行为。

## 重要修复：输出太快会关闭终端（alpha.36 起就有）

- **现象**：服务器输出比终端显示快时（例如在局域网里 `cat` 大文件，或界面短时间卡住），积压超过 128 块数据，Core 就永久关闭这个终端通道。按块计数，所以小数据包时积压几十 KB 就会触发，并不是提示里写的 4 MiB。堡垒机会话只能回控制器重新唤醒。
- **原因**：SSH.NET 给每个通道 2 GiB 窗口，等于没有流控，服务器不会等客户端。
- **修复**：Studio 的 SSH 终端改用真正的通道流控。窗口 2 MiB（与 OpenSSH 相同），终端读走多少才归还多少；读不过来时服务器暂停发送，文件、监控等其他通道不受影响。还没显示出来的终端（批量打开、后台页签）同样适用。
- 不遵守窗口的服务器仍受 4 MiB 上限保护：只关闭这个终端，连接保留。
- 这是可选参数，`Forterm.Desktop` 不传，行为不变。
- Telnet 终端同样处理：读不过来时由 TCP 让服务器等待，不再关闭终端。

| 实测（Release 构建，macOS，回环 paramiko 服务器；由审查代理测量） | 修复前 | 修复后 |
|---|---|---|
| 20 MB/s，4 KB 包，什么都不开 | 正常 | 正常 |
| 20 MB/s，4 KB 包，录制中 | 0.2 秒后终端被关闭 | 正常 |
| 20 MB/s，4 KB 包，5 万行回滚里反复查找 | 0.1 秒后终端被关闭 | 正常 |
| 40 MB/s，4 KB 包，什么都不开 | 终端被关闭 | 正常 |
| 不限速（>300 MB/s） | 终端被关闭 | 正常，全部输出到达 |
| 往返 100 毫秒 / 200 毫秒的链路 | — | 14 MB/s / 7.5 MB/s（受 2 MiB 窗口限制，与 OpenSSH 相同） |

洪泛期间服务器每 20 毫秒换一次密钥（约 970 次）、洪泛中途关闭通道（280 次），都没有出错。

## 重要修复：macOS 上可能同时开出两个主程序（alpha.1 起就有）

- **现象**：从不同终端、或访达和终端各启动一次，会各自成为“第一个实例”。后启动的会接管同名管道，之后的唤醒都去了它那里；两个进程共用一个数据目录。3 秒去重在各自进程内进行，所以跨实例也失效。
- **原因**：.NET 的命名互斥量在 macOS / Linux 上默认按 POSIX 会话隔离。以往的测试都从同一个进程启动，所以没有发现；这次首次运行原生窗口时发现。
- **修复**：Studio 改用每用户一个的互斥量（`NamedWaitHandleOptions`，跨会话、仅当前用户）。新增测试在另一个 POSIX 会话里启动第二个实例，修复前失败、修复后通过。
- **Windows**：命名互斥量按登录会话共用，读代码判断不受影响，行为没有改（没有在 Windows 上运行）。Core 里是可选参数，`Forterm.Desktop` 不传。

## 内容

### 右键菜单

- 在终端里点右键显示菜单：复制、粘贴、全选、查找、快速命令、记录会话、新建终端、滚动到底部、清空显示、终端设置。菜单在松开右键时打开。
- 程序接管鼠标时（htop、vim 等），右键交给程序；按住 Shift 仍由终端处理。
- 设置里可以改回以前的方式“复制 / 粘贴”（有选中内容时复制，没有时粘贴）。这种方式下粘贴同样经过下面的确认。
- “清空显示”只清本机显示和回滚，不向服务器发送任何内容。

### 粘贴确认

- 快捷键、右键菜单、右键直接粘贴，全部经过同一个检查点：
  - 换行统一成回车；其余控制字符一律去掉（ESC、Ctrl+C、Ctrl+U、退格等），所以剪贴板里的文字不能提前结束“括号粘贴”，也不能操作行编辑器；改变显示顺序的双向控制字符也去掉。制表符保留。
  - 多行、以换行结尾、超过 4096 个字符或去掉过控制字符时，先显示将要粘贴的内容再确认。可以在设置里关闭确认；清理控制字符不能关闭。
  - 超过 1 MiB，或只含控制字符时不粘贴，并在状态栏说明。
- 确认期间终端关闭或换成别的会话，内容不会发到另一个终端；确认窗口打开时再次粘贴会被忽略。

### 复制

- 复制时去掉每行末尾用来补满屏宽的空格和末尾空行。以前复制多行时每行都带一串空格，粘贴回 shell 会出错（例如续行符 `\` 后面多出空格）。
- 新增“选中即复制”（默认关闭）：只有鼠标在终端里做出的新选择才会写剪贴板；拖滚动条、Ctrl+点击链接、程序接管鼠标时都不会。

### 自定义高亮

- 默认规则：网址、IPv4 地址、版本号，以及错误 / 警告 / 成功类词语，与截图里的网址、地址上色一致。可以增删、排序、停用、改颜色、区分大小写，也可以恢复默认或整体关闭。
- 只影响显示，不向服务器发送内容。程序自己设过文字色或背景色的文字、反色文字、全屏程序（备用屏幕）和反色屏幕不改。颜色取自当前终端配色，换配色后一起换。
- 规则是正则表达式，用 .NET 的非回溯引擎。某条规则连续三行都超过 50 毫秒，就停用到程序退出，并在设置页说明；写法不能用的规则也写明原因。其余规则照常生效。
- 按屏幕上的一行匹配，被折行的文字不跨行匹配。

### 光标和回滚行数

- 光标样式（竖线 / 方块 / 下划线）和闪烁立即生效；程序自己设置过的光标不会被别的设置改动抹掉。
- 回滚行数 1000–50000，默认 5000（与以前相同），对新打开的终端生效。

### 终端内查找

- 工具栏按钮、右键菜单，或快捷键（macOS `Cmd+F`，其他系统 `Ctrl+Shift+F`）。在整个回滚里查找并标出匹配，从最新的开始；Enter 往上，Shift+Enter 往下；可区分大小写。
- 每次跳转都会重新查找，新到的输出计入，当前位置不变。跨行折断的匹配算一处。超过 1 万处时保留最新的 1 万处。
- 切换终端页签、切到别的会话再回来、进出全屏程序，都跟着当前显示的内容查找。
- 标记颜色按配色取，测试逐个配色计算了对比度。

### 快速命令

- 在“系统配置 → 快速命令”里增删改、排序；在终端工具栏的闪电按钮（可搜索）或右键菜单里点一下，就输入到当前终端。可设“自动回车”和“每次执行前确认”；支持多行。
- **控制器唤醒的会话**：不会自动写入任何内容；第一次使用快速命令前会显示命令并确认，同一会话之后不再询问（设了“每次执行前确认”的除外）。这个确认和“执行 CD 命令到终端”的确认互相独立。
- 确认期间终端被关闭或换成别的 shell，就不发送。命令列表打开时切换到别的会话（例如有新的唤醒），列表自动关闭，不会输入到另一个会话。
- 内容不能含控制字符；以明文保存在数据目录的 `quick-commands.json`，页面上写明“请不要写密码”；不随连接导出。文件损坏时不读取也不覆盖，本次使用临时空列表并提示。

### 会话记录

- 在右键菜单里手动开始，由用户选择保存位置；从光标所在的那一行起，只记录这个终端的**输出**，不记录按键；不会自动开始。控制器唤醒的会话会先确认一次（堡垒机内容落到本机可能违反单位规定）。
- 记录成纯文本：去掉颜色、标题等控制序列；行内编辑、退格、进度条按最后的样子记录。**超过屏宽的命令**按终端实际列数处理折行，用真实 bash 3.2 和 zsh 5.9 在 40 列下的输出（输入、在行首行尾修改、退格越过折行处、中文、整行删除）做测试。
- vim、less、htop 等切换到备用屏幕的程序只记一行“画面不记录”；top 这类直接在原屏幕刷新的程序会逐屏记录。
- 写盘在独立线程，不占终端的读线程。写得慢时终端输出跟着放慢，记录不缺内容；磁盘 3 秒没有任何进展时停止记录，终端继续。自己停止的记录会在文件末尾写明“# 记录在此停止：原因”。
- 新文件独占创建，**不覆盖已有文件**；macOS / Linux 上文件权限为仅本人可读写。上限 256 MiB。页签上有红点。

### 设置

- “通用终端”新增光标、回滚行数、右键菜单、粘贴确认、选中即复制、会话记录说明；新增“自定义高亮”“快速命令”两个分类，都能被搜索到。
- “恢复默认外观”改为只重置外观项，其余设置（包括本版新增的）都保留。
- 设置文件的大小上限从 64 KiB 提高到 512 KiB，留出余量：规则写满时约 62 KB，已接近旧上限。
- **设置文件无法读取时**（写坏、过大、被占用）：启动时提示，本次用默认设置；下次保存前把原文件改名为 `preferences.unreadable-时间.json` 保留。以前会静默用默认值并在下次保存时覆盖掉。

## 改动范围

- **Core（只增加，默认不变）**：`SharedSshSession.OpenShellAsync(…, flowControl)`、`InstanceBroker.StartAsync(…, acrossSessions)`、`SshPtyConnection` 的流控读队列、`TelnetPtyConnection.ConnectAsync(…, flowControl)`。`Forterm.Desktop` 不传这些参数；它原来“积压就关闭终端”的行为由旧测试继续覆盖。
- **vendor/SSH.NET**：`Channel` 增加可选的有限窗口和按读取量归还；`ShellStream`、`SshClient` 透传。
- **vendor/Iciclecreek.Terminal**：粘贴 / 复制 / 高亮的钩子（默认为空，行为不变）、查找加锁、读取光标所在行。补丁标识改为 `review-highlight-v17`。
- **vendor/XTerm.NET**：查找可保留最新结果、按匹配计数、跟随当前缓冲区。补丁标识改为 `search-newest-v16`。
- 三个库的补丁记录都已重建：用上游原文件加补丁还原，逐个文件核对与当前代码一致。`Iciclecreek.Terminal` 的记录在断线前就已落后，这次一并补齐。

### 原生 Mac 窗口运行（首次）

2026-11-24，macOS arm64，Release 自包含发布，独立的临时数据目录，服务器是本机回环测试服务器（`ssh_fixture.py`，它的 shell 只回显输入）。没有碰用户配置和钥匙串。

| 场景 | 结果 |
|---|---|
| `xshell` 入口唤醒 | 窗口打开（1440×860）；认证 1 次、shell 1 个、SFTP 1 个；终端没有被写入任何字节；pty 随真实窗口调整为 91×43 |
| 修复前：另一会话的两次唤醒 | 起了第二个主程序窗口（上面的缺陷） |
| 修复后：另一会话、3 秒内两次相同唤醒 | 始终只有一个实例；只多开一个会话；两个入口退出码都是 0 |
| `xftp` 唤醒 | 只开 SFTP，shell 数不变 |
| 带无效参数 `-bogus` | 转交给运行中的实例，没有建立连接 |
| `forterm-diagnose` | 退出码 0，`networkRequested: false`，输出不含密码 |

## 未验证 / 限制

- 以下都没有运行过：Windows 实机（ConPTY、DPI、输入法）、真实控制器唤醒和堡垒机、真实 OpenSSH / Go / MINA 服务器、Windows 凭据管理器和 Mac 钥匙串的真实读写。Windows CI 工作流仍未运行（代码没有提交推送）。
- 流控只在 paramiko 回环服务器上测过。窗口 2 MiB 与 OpenSSH 客户端相同；高延迟链路上单个终端的吞吐受它限制。
- **Windows 上 `Ctrl+Shift+F`** 通常是微软拼音的简繁切换键，可能收不到；工具栏按钮和右键菜单可以打开查找。
- 录制：移动到已经结束的行（例如多行进度条原地刷新）只能近似记录，会一条条记下来；命令行折行处的宽字符前，bash / zsh 自己补的空格会留在记录里；磁盘很慢时关闭窗口，末尾可能写不完。
- 快速命令：写入失败但通道看着还活着时，状态栏仍显示“已输入”。
- 查找每次跳转都重新扫描整个回滚，5 万行约 20 毫秒。
- **退回 alpha.5**：alpha.5 能读取设置文件，但一旦保存会丢掉本版新增的设置；`quick-commands.json` 不受影响。连接库格式没有变化。
- 连接库、隧道、设置的其他限制见 `docs/STUDIO-ALPHA4-DELIVERY.md`、`docs/STUDIO-ALPHA5-DELIVERY.md`。
