# Forterm Studio 0.4.0-alpha.2 交付说明（2026-11-22）

阶段 2：连接库。计划见 `docs/STUDIO-REBUILD-PLAN.md`；阶段 1 见 `docs/STUDIO-ALPHA1-DELIVERY.md`。

## 内容

**连接库（首页，参考截图 01）**
- 协议页签 SSH（含 SFTP）/ FTP / Telnet；右上“导入”“导出全部”。
- 左侧分组树：全部 → 收藏(n) / 最近(n) / 常用(n) / 分组（可嵌套，计数含子分组）/ 未分组连接；可收起；右键新建分组、子分组、重命名、删除（删除只移动其中连接到上级，不删连接）。双击树中连接直接连接。
- 主机表：勾选、收藏星标、协议标识、延迟、名称、地址（复制）、备注、操作（连接 / 编辑 / 更多：收藏、复制连接、复制地址、删除）。按延迟/名称/地址排序；搜索名称、地址、用户、备注及 `user@host`。双击行连接。
- 批量：已选 N 项 → 导出 / 复制 / 删除 / 并发（同时打开，超过 10 个先确认）。
- 延迟：只测 TCP 握手耗时（含域名解析），不发送数据、不认证；8 路并发、每次最多 200 个、缓存 1 分钟；经跳板或代理的连接显示“跳板”“代理”，不测。

**连接编辑（参考截图 03–05）**：基本信息 / 连接设置 / 跳板机 / 代理设置 / 其他设置 / 初始化六节，左侧锚点导航与滚动高亮；测试连接 / 取消 / 创建（保存）。
- 基本信息：名称、分组、协议、地址+端口、验证方式（密码 / 键盘交互 / 私钥 / SSH Agent）、用户/密码、保存或清除已保存密码、私钥文件与口令、备注。
- 连接设置：超时（毫秒）、SSH 协议心跳（毫秒，0 关闭）、终端显示编码（UTF-8 / GBK / GB18030 / Big5 / Shift_JIS / EUC-KR / ISO-8859-1）。
- 跳板机：从已保存的 SSH 连接中选择，按顺序排列（第一项最先连接），可上移/下移/移除，最多 4 级。
- 代理：`socks5://` 或 `http://`，用于第一跳；可禁用；拒绝在 URL 中写账号密码。
- 其他设置：终端类型（TERM）。
- 初始化：默认路径（文件区起始目录）、初始执行（终端打开后逐行写入）、保活命令 + 周期（按周期写入终端）。按用户决定实现；只作用于保存的连接，唤醒的临时会话不写入。

**存储与安全**
- 元数据 `library.json`（Studio 数据目录）同目录临时文件 + 原子替换；载入和保存都校验；文件无法读取时本次用临时空库并提示，不覆盖原文件。
- 密码与私钥口令只进系统凭据（钥匙串 / 凭据管理器），没有明文回退；元数据只有“已保存”标记。删除连接同时移除其凭据。
- 导出不含任何秘密、已保存标记、使用记录；导入分配新标识，跳板链只在导入集合内映射，不继承凭据和主机指纹信任。
- 测试连接确认的主机指纹不写入信任库。
- 未保存密码时连接前询问一次，仅本次使用。

**Core 的向后兼容改动**（旧 `Forterm.Desktop` 用默认值，行为不变）：`SessionConnectOptions` 新增 `ConnectTimeoutSeconds`、`Proxy`（HTTP/SOCKS5，第一跳）；`OpenShellAsync` 新增可选 TERM 参数并校验。测试夹具 `ssh_fixture.py` 额外记录请求的 TERM。

**修复**：工作区不在屏幕上时（另一页签被选中、并发连接、后台唤醒），终端控件尚无模板，旧逻辑会报“终端通道不可用”。现在等页签显示后再接上，期间输出由连接的有界读队列缓冲。

## 未验证 / 限制

- Windows 实机、真实控制器唤醒、Windows 凭据管理器读写均未运行；Mac 钥匙串在测试中用内存替身，真实读写未验。
- 本机环境中，文档保留地址（不可达）也显示约 1 ms 延迟：有本地代理/VPN 接管 TCP 握手时，TCP 延迟不能反映真实可达性。这是只测 TCP 握手的固有局限。
- 系统图标列显示协议标识，不识别操作系统；“信息”列（已打开会话的指标）随阶段 4 监控接入。
- 编辑器暂未提供：会话环境变量、X11 转发（SSH.NET 不支持）、主机密钥/加密/密钥交换算法、禁止列表监控、禁用 pwd 自动跳转——分别在后续阶段接入或说明不支持。
- 跳板链只按目标连接的列表走，跳板自身的跳板链不递归。
- 旧 alpha.36 配置的显式导入尚未接入（本阶段只导入 Studio 导出文件）。
