# Forterm Studio 0.4.0-alpha.9 交付说明（2026-11-25）

本版主要是**让 Windows 用户真正用起来**：安装包、控制器接入页、几处只在 Windows 上出现的问题，以及用户在真实堡垒机和 Windows 上试用预览版后提出的几件事。计划和决定见 `docs/STUDIO-REBUILD-PLAN.md`，上一版见 `docs/STUDIO-ALPHA8-DELIVERY.md`。

Core 和 vendor 的 SSH.NET 有增量改动，`Forterm.Desktop` 的行为不变（见“改动范围”）；`Forterm.Desktop` 的源码、alpha.8 及更早的包、四个预览包和检查点都没有改动。

## 内容

### Windows 安装包（新）

- `Forterm-Studio-0.4.0-alpha.9-windows-x64-setup.exe`：只为当前用户安装，不需要管理员权限，默认装到 `%LOCALAPPDATA%\Programs\Forterm Studio`。开始菜单有快捷方式，桌面快捷方式可选。ZIP 版仍然提供，解压即用。
- **升级装在原来的文件夹里**，控制器里填好的 xshell / xftp 路径不用改。设置、连接、凭据都在数据目录（`%LOCALAPPDATA%\Forterm\Studio`），安装、升级、卸载都不动它们。
- **只替换和删除自己装的文件**：
  - 选了一个已经有别人文件的文件夹（例如真正的 Xshell 所在文件夹，或者有同名 `README.txt` 的文件夹）会被拒绝，退出码 3，文件夹保持原样。
  - 卸载只删除安装清单里的文件；用户自己放进去的文件和文件夹保留。
  - 装了两份（换过文件夹）时，卸载其中一份不会影响另一份的注册表项和快捷方式。
- **Forterm、xshell、xftp 任何一个在运行时**，安装和卸载都放弃，退出码 4，什么都不改（不会结束正在运行的程序，不会断开会话）。
- 有文件写不进去时不会报告成功：新文件写不进去退出码 2，旧版本删不干净退出码 5，不会留下新旧混合的文件还报告成功；安装位置在动手之前就记下，下一次安装回到同一个文件夹补齐。卸载没删干净时同样是 5。
- 没有数字签名，第一次运行 Windows 可能提示“更多信息 → 仍要运行”。

### 控制器接入（新，系统配置 → 控制器接入）

- 显示 xshell / xftp 两个入口的完整路径，可以复制，以及文件是否在。
- “最近的唤醒”：本次运行以来控制器唤醒过哪个入口、什么时间、结果（打开了 / 失败原因）。只记在内存里，**不记任何参数**（地址、账号、票据都不记）；最多 8 条，所有窗口共用一份。
- 点了没反应时先看这里：没有记录，多半是控制器没有启动这两个程序。

### 入口

- **同时到达的多次唤醒都会被接收**。以前（alpha.1–8 都有）控制器同一时刻打开几个会话时，可能有一个入口等不到主程序、退出码 4，那个会话就没有打开。现在主程序总会多开一个等待的管道。（macOS 上复现过；审查时 40 个入口进程同时启动，全部接收。）
- 入口已经放弃等待（退出码 4，用户已被告知）之后，主程序不会再晚一步把它打开，避免同一张票据开出两个会话。
- 入口失败时在 Windows 上弹出说明（控制器自己通常什么都不显示）：缺少 `Forterm.exe`（2）、主程序没有启动（3）、正在运行的 Forterm 没有接收（4）。说明里不含任何参数；`--diagnose` 不弹；最多等 60 秒。
- 更正：此前回答过“单独拷走的 xshell.exe 会以 2 退出”。准确地说，退出码 2 只适用于同一文件夹里只少了 `Forterm.exe`；单独一个 `xshell.exe` 没有它依赖的文件，会直接出现 .NET 的启动错误。
- 程序、入口和窗口有了图标。

### Windows 上的界面

以下问题只在 Windows 上出现，是 Windows CI 的真实窗口截图和用户的实机截图发现的：

1. **右上角的齿轮（系统配置）被一个“全屏”按钮盖住，鼠标点不到**（alpha.1–8 都有）。Avalonia 在 Windows 上会在窗口自己的标题栏上再画一层标题和四个按钮。现在去掉全屏按钮，并给另外三个按钮留出位置。
2. **左上角的标题文字压在图标上**（预览 1 仍有，用户实机截图）。这一层的显示状态由 Avalonia 的模板自己决定，样式改不了；改为透明并隐藏文字，测试用 Avalonia 真实的模板。
3. **窗口比屏幕大**（低分辨率或高缩放时，底部状态栏在屏幕外）。现在打开时不超过屏幕工作区并居中。
4. **中文显示成繁体字形**：Windows 上界面字体回退到了繁体中文字体。现在依次用微软雅黑 UI、微软雅黑、宋体。

### 服务器登录后就断开：说清楚断在哪一步（用户 11-25 在真实堡垒机上遇到）

用户的截图：登录成功，随后终端和文件都打不开，提示里是英文的 “Cannot access a disposed object” 和 “An established connection was aborted by the server”。原因还没有确定（需要用户的诊断），这一版先把能查的都做了：

- **说明是哪一步断的、谁断的、服务器怎么说**：例如“登录已通过，还没有请求打开通道，服务器没有说明原因就关闭了连接”“服务器拒绝打开通道（代码 1，服务器的说明：……）”“连接被强行重置（服务器，或中间的防火墙、安全网关）”。不再显示英文异常。
- 连接已经断了以后，不再继续打开文件通道而报出 “disposed object”；先出现的原因不会被后来的状态覆盖。
- 会话用到一半服务器断开（管理员踢下线、超时）时立刻说明，带上服务器的原话；以前要等 15 秒，还被说成协议保活没有应答。
- 本程序自己放弃的连接照实说：对方不是 SSH 服务器、SSH 版本不支持、主机密钥没有通过核对、双方没有共同的算法；常见的网络错误（拒绝连接、找不到主机名、网络不通）也用中文说明。
- **复制连接诊断**：会话栏、文件栏和命令面板里都有。内容是双方交换了哪些协议消息（名称和毫秒）、协商的算法、本程序标识、断在哪一步；**不包含地址、用户名、密码、票据、终端内容和文件名**。
  - 服务器写的文字（断开和拒绝的原因、请求名、登录方式、服务器标识）单独记录，复制时再隐去一遍：IP 地址（含 IPv6）、带点的主机名、`用户@主机`、GUID 和 20 位以上的字母数字串、本次连接的地址、用户名和标题、跳板机，以及服务器复述的控制器密码（密码只以带密钥的散列保存，用来认出它）。服务器标识只记版本，后面的说明不记。
  - 最多记前 100 条和最后 60 条，中间写省略了几行。通道编号写明是哪一方的。
- **登录提示**（服务器在登录时显示的 banner）现在会显示；以前提示来得早时会丢。
- 通道的请求方式改成和常见客户端一致（只对 Studio，`Forterm.Desktop` 不变）：
  - 服务器拒绝打开通道时只请求一次，并显示它给的原因（SSH 库原来会连续重试 10 次，把原因丢掉；有的堡垒机会把这当成异常而断开）。
  - 数据包 32 KiB（原来 64 KiB），终端模式列表不再是空的。
- 服务器文字里的控制字符和不可见字符（方向标记、零宽字符、BOM 等）一律去掉再显示。

### 关联已打开的文件会话（用户 11-25 提出）

- “文件通道不可用的时候让我可以去关联已经打开的 xftp 会话”：终端会话的文件栏里有“关联文件会话”，列出**已经打开**的 SFTP / FTP 会话（xftp 唤醒的、保存的都可以），由用户自己选；**从不按主机、地址或用户名自动匹配**。
- 关联后文件栏显示那个会话的文件，标题写明“正在显示“某某”的文件”；被关联的会话的页签收起，解除关联、或者终端会话关闭时恢复。连接本身从不关闭、不重新认证、不重放票据。
- 文件操作（上传、下载、编辑、删除、压缩、权限）作用在文件会话上；“CD 到终端”“新建终端到当前目录”和打开的编辑器去当前在前面、显示这些文件的会话。编辑器保存和传输仍属于原来的文件会话。同一个文件只开一份草稿，已经在别的会话里打开时就切过去。
- 关闭终端会话时，在关联会话里打开、还没保存的草稿会一起列出来确认。
- 自己有文件栏的会话也可以临时显示别的会话，再切回来；一个终端会话同时只关联一个文件会话。被关联的会话断开时，文件栏会说明。

### 关闭监控不再连终端一起关掉（用户 11-25 提出）

- 原因：点一下监控栏的 ×，监控栏收起，终端栏的 × 正好移到鼠标下面；双击或连点时，第二下就关掉了终端（会话页签也一样）。用户的连接本身没有断。
- 现在所有 ×（页签和栏）和鼠标中键关闭页签，都忽略双击的第二下，以及“刚关掉一个东西之后半秒内”的点击：那时下一个页签或 × 刚移到鼠标下面。收起终端栏时提示“终端栏已收起，会话没有断开”，可以一键恢复；收起监控后键盘回到终端。

### 传输速度（用户 11-25 提出）

- 传输管理里每一项显示实时速度和剩余时间，完成后显示平均速度；标题显示总上传、总下载速度。
- 速度按最近 3 秒内实际有数据流动的时间计算，停顿不算进去；很短的传输（不到 50 毫秒）不报平均速度。列表不再整行重建，滚动和选中不跳。

## 改动范围

- Studio：`avalonia/src/Forterm.Studio` 和它的测试。新文件：`Services/ControllerAccess.cs`、`Services/CloseGuard.cs`、`ViewModels/WorkspaceViewModel.Links.cs`、`Assets/forterm.ico`，测试 `Alpha9Tests.cs`、`HangUpTests.cs`、`LinkTests.cs`、`TransferSpeedTests.cs`、`Alpha9ReviewTests.cs`。没有新增依赖包。
- 入口 `Forterm.Launcher`：失败时的说明框、图标。参数仍按数组原样转交，不经过 shell。
- Core（增量，`Forterm.Desktop` 的行为不变）：
  - `InstanceBroker.StartAsync(…, queue: true)`；不带它的 `Listen` 不变。
  - `SshTrace`（新）、`SshErrors`（新）；`SessionConnectOptions.CommonChannels` 和 `Trace`，默认关闭和空。
  - `SharedSshSession`：只在 `CommonChannels` 时请求一次通道、32 KiB 数据包、非空的终端模式；只在有 `Trace` 时听服务器的告别。
- vendor：SSH.NET 保留通道被拒绝的原因（`SshChannelOpenException`，继承原来的异常类型、消息不变）、可设数据包大小和终端模式、几种消息的 `ToString`。`vendor/patches/sshnet-shared-transport.patch` 已重新生成并核对。终端组件没有改。
- 打包：`packaging/studio-installer.nsi`、`packaging/README.txt`、`tooling/package-studio-windows.py`、`tooling/check-studio-installer.ps1`（只在 CI 运行）、`tooling/native-check.py`、`tooling/make-icon.py`；`.github/workflows/studio-windows.yml` 增加安装、升级、卸载和真实窗口检查。
- `tooling/ssh_fixture.py`：新增 `FIXTURE_ODD`、`FIXTURE_TEXT`、`FIXTURE_BANNER` 和命令 `drop`、`bye`，`stats` 增加 `opens`、`ptyModes`；默认行为不变。

## 未验证 / 限制

- **真实堡垒机“登录后断开”的原因还没有确定。** 本版排除了几个可能（重复请求通道、64 KiB 数据包、空的终端模式），其余可能是堡垒机只接受特定客户端、票据或目标的问题。请用本版再试一次；仍断开时点“复制连接诊断”发回来。本程序不会冒充 Xshell 的客户端标识。
- 以下都没有运行过：Windows 10/11 桌面实机上的安装包（SmartScreen、杀毒软件）、ConPTY、DPI、输入法、AltGr、真实拖放；真实控制器唤醒；Windows 凭据管理器和 Mac 钥匙串的真实读写；屏幕阅读器。
- 控制器用隐藏窗口启动入口时，入口的失败说明框可能看不见；入口最多等它 60 秒，退出码不变。
- 关闭保护对整个程序共用：一个窗口里刚关掉东西，另一个窗口的 × 半秒内也不响应。半秒内想关的下一个页签需要再点一次。
- 连接诊断宁可多隐去：带点的文件名、`用户@主机` 形式的文字、20 位以上的字母数字串都会被隐去。经跳板机连接时，跳板机断开会被记成目标服务器断开。
- 安装包没有数字签名。
- 其他限制见 `docs/STUDIO-ALPHA4-DELIVERY.md` 到 `docs/STUDIO-ALPHA8-DELIVERY.md`。
