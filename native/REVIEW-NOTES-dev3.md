# 0.2.2-dev.3 审查候选：只修手动计时归属

保留dev.2原包。本次应用功能/配置/上传/VT未再改；差异是uiresponse事件/动作配对、明确缺样本/censored及版本身份。仍非正式“Windows卡顿已修”发行，不在未审查协调时运行Windows程序。

显式运行：`forterm-diagnose.exe --ui-check`。与此前相同的临时0/1000合成配置和手动动作；不读现有连接配置/OS凭据、不网络/本地终端，所有正常controller参数仍按原规则转交。

只有同一阶段、启用的测试按钮上的左键按下/释放才能形成递增事件ID；handler通过按钮的pointer Tapped路径按FIFO消费配对。键盘/可访问性/直接回调无确认配对时记unmatched及原因，时延字段缺省而非0。超过1秒甚至12秒的有效配对仍保留完整数值，没有耗时过滤。阶段切换/关闭/容量边界会记录censored及计数。光标坐标只在进程内用于命中判断，从不写入报告。

handlerToRaster只是工具条marker生成；动作产生弹窗时不把操作者等待当绘制延迟，明确censored。合并/切阶段/关闭前未观察marker也列原因，不默认为0或通过。它不是弹窗可见时刻，也不是DWM/RDP最终呈现。报告保留handler CPU和配对状态、各类计数。

本次只做定向race测试和Windows x64交叉构建/包摘要验证；没有Windows运行或无变化整套重测。完整应用的实际Win按钮样本、最新高DPI与正式三包仍要收敛后交付。
