# Forterm

面向 Windows 10/11 x64 的堡垒机终端工具。通过兼容 Xshell/Xftp 的启动参数，接收单点控制器发起的 SSH/SFTP 临时会话。

技术栈：Electron 45、TypeScript、React、xterm.js、ssh2、node-pty。三个兼容入口使用很小的 Go 启动器转交参数；桌面客户端核心采用 Electron。

## 下载包与入口

构建产物位于 `release/`：

| 文件 | 用途 |
| --- | --- |
| `Forterm-0.1.7-x64.zip` | 推荐用于控制器接入。解压后保留整个目录，包含四个入口及共享运行时 |
| `Forterm-0.1.7-x64-setup.exe` | 按用户安装；控制器路径选择安装目录中的对应入口 |
| `Forterm-0.1.7-x64-portable.exe` | 自解压便携应用，适合直接运行或接收 SSH 参数 |

解压目录 / 安装目录中的入口：

| 入口 | 行为 |
| --- | --- |
| `forterm.exe` | 主界面；根据 SSH/SFTP URL 打开终端或文件会话 |
| `xshell.exe` | 接收 Xshell 启动格式，转交主应用 |
| `xftp.exe` | 接收相同格式，SSH/SFTP URL 进入 SFTP；FTP URL 保留真实 FTP |
| `forterm-diagnose.exe` | 仅显示脱敏参数报告，不建立网络连接 |

**兼容入口需要同目录的 `forterm.exe`、`resources/` 等完整文件，不能单独复制 exe。** 如需要四个独立的可选路径，请使用 ZIP 或安装包；自解压便携版通过 `--diagnose` 开启诊断。

## 接入现有控制器

1. 在单点控制器中记录原来的 Xshell 路径，然后将其改为解压目录中的 `forterm-diagnose.exe`。
2. 通过堡垒机网页重新申请一次连接。诊断窗口会显示参数数量、类型和已识别的选项。
3. 点击“导出报告”，得到脱敏 JSON。未知参数、URL 内的用户名、密码、地址以及标签内容默认隐藏。原始命令行不写入文件。
4. 报告显示“已识别”时，将控制器路径改成同目录的 `xshell.exe`，再次申请一个新的临时会话。Xftp 入口改成 `xftp.exe`。
5. 首次连接核对堡垒机代理端口的 SSH 主机指纹。需要动态验证码时，应用会弹出交互认证窗口。

已过期的临时 URL 不能用于验证新的连接。断线后回到控制器重新授权；Forterm 不自动复用控制器的临时密码。

### 0.1.7：左文件多标签、中央编辑分屏、右监控

终端工作区的文件区在左、监控在右，各自可收起和拖宽。顶部“同时显示”打开两侧；监控仍属于当前终端资产，不随文件来源切换。最左侧整块连接/堡垒机导航顶部有“收起连接栏”，收起后工作区顶部保留固定的“展开连接栏”。按钮支持Enter/Space，记住开关和原宽；收起不会改连接、文件标签或草稿。

左侧通过“关联文件连接”明确添加独立SFTP/FTP来源，在文件标签间切换；各自保留目录、筛选、排序和滚动。协议、名称和连接状态可见，SFTP的“SSH就绪”表示transport状态，文件通道权限错误另行提示。已关联来源（包括非活动标签）隐藏顶部重复标签；关闭文件标签仅解除关联，底层连接继续运行。涉及草稿或传输时有说明与确认；最后解除关联后顶部文件标签恢复。旧单来源映射兼容迁移，无共享IP自动匹配。

双击目录进入；双击可编辑文本在当前终端区域分屏打开，重复双击聚焦原文档，不新建会话/窗口。同名文件按来源区分，浏览来源切换后原草稿仍保留，保存绑定文档原连接，编辑器标题显示来源。FTP、不支持文本等明确提示，双击不会自动下载。左右/底部停靠、尺寸与草稿仍保留；中央空间不足时暂用底部分屏，放大恢复所选停靠。窄工具栏使用左右滚动入口。

具体门户登录/资产/票据provider仍未适配，不能直接登录堡垒机；没有新增门户请求或假资产。原控制器入口、本地账户/TOTP和之前的传输队列、文本安全规则继续使用。

### 0.1.6 阶段版：隐藏已关联文件标签

在资产工作区选择独立 SFTP/FTP 文件会话后，顶部对应文件标签隐藏，底层连接、文件编辑和传输继续使用。更换/解除关联，或最后一个关联工作区关闭后，原文件标签恢复；共享关联存在时继续隐藏。标签快捷键和“关闭其他标签”只作用于可见工作区，避免误关隐藏文件源。

包含下一阶段的主进程接入基础，但**门户内置登录/授权资产仍待厂商适配，目前不能直接登录堡垒机**。未注册提供器时“登录堡垒机”禁用，不产生门户请求或展示合成资产。现有网页/控制器 Xshell/Xftp 入口和本地账户/TOTP 配置继续使用。可按 `docs/BASTION-CONTRACT-TEMPLATE.md` 提供脱敏契约，后续再接具体提供器。

### 0.1.5：传输队列、账户与代码编辑工作区

文件传输按文件连接串行排队，显示排队/运行/成功/失败/取消状态。覆盖检查在队列中执行，目录元数据在文件间隙处理；目录失败保留最后可用列表，完成后合并刷新。停滞或取消仅重置文件通道并停止未开始项，SSH 终端保留；不会自动重试上传或重新使用临时票据。

同一资产工作区可以明确选择独立 SFTP/FTP 连接，也可继续复用当前 SSH 的 SFTP。系统不按共享代理 IP 或临时用户名自动关联。文件编辑/传输绑定所选文件源，监控仍属于当前 SSH；关闭资产工作区不会自动关闭独立共享文件连接。FTP 为被动明文 FTP，无 FTPS/主动模式；支持列表/上传/下载/逐项递归删除，在线安全编辑和排他新建文件暂不支持。

代码编辑器默认右侧，可停靠左侧/底部、拖动尺寸、收起、重置与持久化。提供行号、缩进参考、光标行列和 YAML/JSON/XML/Shell/INI/properties/JS/TS 本地语法高亮。空白与换行标记默认关闭，可手动开启并记住；无自动格式化、尾空格清理或换行追加。保留原 BOM、统一 LF/CRLF 与无尾换行；混合换行先只读，需要明确转换。新文件是内存草稿，首次显式保存才排他创建，同名不覆盖。保存后文件列表自动刷新。

文件/目录/空白区、代码、终端、标签支持右键和键盘菜单。非空目录删除先确认完整路径及全部子项，有 2000 项/32 层/两分钟边界；取消或失败会报告已确认删除数量，不能回滚。SFTP 链接只删除链接，FTP 链接或不明类型拒绝递归；权限编辑保留特殊位，不递归、不改所有者、不自动设为 777。FTP 仅在 SITE CHMOD 能力与原权限均可核验时开放，未知权限不伪装成 000。

终端支持 Ctrl+Shift+C/V、Ctrl+V、Shift+Insert 和 macOS ⌘；有选区 Ctrl+C 复制，无选区保留中断。所有粘贴入口统一处理，多行或末尾换行先预览确认，不自动追加 Enter；切换焦点/会话时过期请求失效。编辑器和普通输入框保留标准剪贴板与撤销行为。浅色主题包含完整 xterm ANSI 调色板，切换无需重新连接。

侧栏“堡垒机”支持多账户名称/入口/用户名及独立长期密码与验证器密钥配置。秘密仅经系统 safeStorage 加密保存，无明文回退；重编辑只显示已保存标记，可保留、替换或清除，导出不含秘密。TOTP 使用严格 Base32 或 otpauth TOTP，默认 SHA1/六位/30 秒；主动查看才刷新，隐藏停止，保留手动验证码。是否匹配厂商算法仍待验证。**堡垒机内置登录和资产 API 尚未接通**，现有 Xshell/Xftp 控制器入口继续保留。

### 0.1.4：小窗口与高缩放下的控件可达性

低高度时顶部新建/搜索导航和底部主题栏保留在视口中，连接列表和工作区工具各自滚动；导入/导出位于工具区底部，可用鼠标滚轮或聚焦后 PageDown/Tab 到达。125% / 150% 缩放及长连接列表下均进行了实际按钮点击和键盘操作验证。

欢迎页、纯 SFTP 工作区和窄布局工具栏提供内部滚动；文件/监控同时显示时，以完整控件的可用空间限制分区比例，避免区域尚有高度但按钮无法完整显示。小窗口中的编辑器可内部滚动或收起以腾出空间；传输队列最多占视口高度的 20%，队列内部可滚动，避免展开后挤掉工作区。

### 0.1.3：可拖动的工作区

拖动连接栏、文件/监控侧栏、编辑器或双终端之间的分隔条，实时调整大小。双终端上下和左右分屏分别记住比例，文件与监控“同时显示”时也可以调整两区比例。窗口变小会限制实际尺寸并保留终端与编辑器空间，窗口放大后恢复用户偏好的大小。

分隔条支持 Tab 聚焦后按方向键调整、Shift 加速、Home/End 到最小/最大；Enter 或双击重置单条，顶部“重置布局”恢复全部默认尺寸。布局存于本机，正常退出前立即保存。编辑器标签栏的“收起”保留草稿，点击“展开”恢复高度；右侧收起/展开保留文件导航和监控开关，隐藏期间暂停自动监控，展开后恢复。

修复慢速 shell 通道就绪时首个终端尺寸同步的时序问题。拖动仅改变布局和 PTY 尺寸，不会输入终端命令、触发文件保存或重新认证。

### 0.1.2：同一会话的完整工作区

终端、SFTP 文件管理、在线文本编辑和资源监控复用当前 SSH 连接的独立通道，不需要再次使用临时票据。SSH 会话点击“打开文件浏览”；Xftp 会话点击“在此会话打开终端”。右侧可以选择文件、监控或“同时显示”。某个通道被拒绝时会给出说明，其他可用通道保留。

文件列表支持路径跳转、返回上级、筛选、隐藏文件和排序；双击普通文件或点击在线编辑图标，在右侧打开编辑器（可切换左侧/底部）。支持最多 12 个、每个不超过 1 MiB 的 UTF-8 文本（含 BOM 和 CRLF）；拒绝二进制、无效 UTF-8 与符号链接。草稿仅在窗口内存保留，切换会话和断线不会自动丢弃；关闭文件、会话或窗口会确认未保存内容。强制终止进程或系统故障无法保留内存草稿。

保存前检查原文件内容摘要和元数据，先写同目录临时文件，再次检查冲突后替换；冲突、权限不足或替换失败不会静默覆盖。保存需要目录写权限；不支持替换的服务器会提示失败，不通过删除原文件强制覆盖。SFTP 没有通用的原子比较并交换，最终检查与替换之间仍有短暂竞争窗口；多人同时修改的重要文件应使用外部版本管理。替换保留普通权限位，不承诺保留所有者、ACL、扩展属性或硬链接关系。断线时远程可能遗留 `.forterm-edit-*.tmp` 临时文件，需要人工核对清理。

监控手动读取 Linux 负载、CPU 累计计数、内存、磁盘和网络累计计数，可主动开启每 10 秒刷新；隐藏面板后停止新请求，失败时停止自动刷新。负载不是 CPU 使用率，累计计数不是速率。监控使用独立命令通道，不向终端输入命令，不安装远程程序。

默认开启 15 秒 SSH 协议保活；只对已经打开的 SFTP 通道进行只读路径探测。侧栏“会话心跳”可设置 5–600 秒间隔或关闭，对新会话生效；已有会话保留创建时设置。不向终端注入回车、按键或命令，也不能消除服务器强制会话时限、shell 空闲退出或电脑休眠造成的断线。

主题、字号、侧栏显示和分组折叠状态保留到下次启动。侧栏提供快捷键说明；支持双终端上下/左右分屏和选择第二个会话。快捷键使用 Ctrl/⌘ + Shift 组合，编辑器内 Ctrl/⌘ + S 保存。

### 0.1.1：控制器重复启动处理

同一入口模式、地址、协议和完整认证信息在三秒内重复传入时，只建立一个会话；控制器生成的标签名变化不导致重复连接。诊断模式合并成一张报告，显示“收到 11 次调用 · 已合并 10 次相同连接的重复调用”，并明确提示未建立连接。普通终端也显示合并次数。

兼容入口会等待子程序结束并转交退出状态，避免刚启动主程序就立即退出。主程序已运行时，新子程序完成参数转交后退出。

去重只作用于外部启动入口。不同会话票据、不同密码、SSH/SFTP 模式或显式新窗口请求仍分别处理；手动新建连接不受影响。未知参数无法可靠比较，继续逐次记录。比较使用仅存在本次进程内的随机密钥 HMAC，报告不导出凭据摘要。关闭标签后可立即重新打开；三秒窗口结束后视为新的启动请求。

更新时先退出全部旧版窗口，再解压新版到独立目录，并将控制器路径改为新版目录中的入口。不能只替换兼容入口 exe，因为去重逻辑在共享客户端核心中。

当前兼容以下形式，选项大小写不敏感：

```powershell
.\xshell.exe "ssh://ticket:encoded-password@bastion.example:12024"
.\xshell.exe -url "ssh://ticket:encoded-password@bastion.example:12024"
.\xshell.exe -newtab "开发环境" -url "ssh://ticket:encoded-password@bastion.example:12024"
.\xshell.exe -newwin "ssh://ticket:encoded-password@bastion.example:12024"
.\xshell.exe -url "ssh://user@host.example:22" -i "C:\keys\id_ed25519"
.\xftp.exe -url "sftp://ticket:encoded-password@bastion.example:12024"
.\forterm.exe --diagnose -url "ssh://ticket:encoded-password@bastion.example:12024"
```

密码中特殊字符需要按 URL 规则百分号编码，只解码一次；不进行 shell 字符串拼接。`-newtab` 的值是标签名，`-newwin` 创建新窗口（窗口共享当前工作区）。不支持的参数会显示脱敏诊断，不会忽略后继续连接。

本项目不重放堡垒机网页请求，不读取网页 Cookie、JWT 或审批接口。真实控制器的最终参数格式仍以诊断报告及现场验收为准。支持的是以上调用方式，不宣称兼容 Xshell/Xftp 的全部脚本、会话文件或私有格式。

## 已实现功能

- 中文深色工作区、连接分组与搜索；手动新建、编辑和删除连接。
- 多标签 SSH、终端搜索、调整字号、双终端分屏、独立窗口；可拖动布局、键盘调整和尺寸持久化。
- 密码、SSH 私钥及多轮 keyboard-interactive 认证；首次主机指纹确认和变更提醒。
- 基于保存连接的跳板链，限制循环及过深嵌套。
- SFTP 目录浏览、创建目录、重命名、删除文件 / 空目录；上传、下载、覆盖确认、进度和取消。
- Windows PowerShell / CMD 本地终端（ConPTY）；macOS 本地终端用于开发验证。
- 手动读取 Linux 负载、内存、根目录磁盘和网络计数。
- Forterm JSON 连接配置导入导出；导出不含密码。
- 手动保存的密码使用 Electron safeStorage 系统加密；临时入口凭据不写入连接配置。

SSH 会话的文件浏览需要点击“打开文件浏览”才启用。监控同样手动开启。堡垒机拒绝 SFTP 或 exec 通道时会给出说明，保留原终端。

上传取消后远程可能保留部分文件；下载先写入本地临时文件，成功后才替换目标。当前版本没有断点续传或目录递归传输。传输面板可以取消任务及清理已结束记录。

## 开发与构建

需要 Node.js 22.12+、npm，以及 Go（仅构建三个 Windows 启动器时使用）。

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run test:ui
npm run test:three-columns
npm run test:navigation
npm run test:reachability
npm run test:burst
npm run dist:win
```

`test:workspace`、`test:layout`、`test:lifecycle`、`test:linked-tabs`是当前三列综合验收的兼容别名，执行一次即可；旧独立脚本保留作历史复现，CI不重复运行这些别名。剪贴板与控件可达性另有专用脚本。

`npm run dev -- --diagnose -url 'ssh://ticket:password@localhost:2222'` 可以在开发模式观察诊断报告。

`npm run dist:win` 生成 x64 ZIP、便携 EXE 和 NSIS 安装包。Windows 的 node-pty 预编译 N-API 模块包含在包中。构建时验证其存在；实际 ConPTY 行为需要 Windows 运行验证。

`.github/workflows/windows.yml` 提供 Windows 构建、测试和产物上传流程。仓库上传到 GitHub 后可使用；本次开发没有创建远程仓库或触发远程运行。

应用尚未配置代码签名证书。正式发布时应配置 Windows 签名，并执行 [Windows 验收清单](docs/WINDOWS-ACCEPTANCE.md)。

## 数据与诊断

- 配置使用 Electron `userData` 下的 `vault.json`，Windows 通常为 `%APPDATA%/forterm/`。其中包含连接配置、系统加密的保存密码和已信任的主机指纹。
- 终端输出只保留内存中的最近约 1 MiB，默认不落盘。
- 诊断报告最多保留最近 100 条，仅显式导出时落盘。
- 临时凭据仍会经过 Windows 进程启动参数，这是控制器现有调用方式决定的；Forterm 不另外保存这些参数。
- 未自动注册或接管系统 `ssh://` 协议关联。此版本针对“控制器指定 exe 路径”的接入方式。

自动化覆盖 URL 解析与编码、未知参数脱敏、加密存储边界、真实本机 SSH/SFTP 协议测试、交互认证、指纹拒绝、文件内容比对、SFTP 拒绝后的终端可用性，以及桌面 UI / 本地 PTY / 第二实例转交。

0.1.2 另覆盖保活设置迁移及持久化、真实 SSH/SFTP 保活、四通道并行、在线编辑冲突/权限/大小/编码/替换失败、传输取消和桌面草稿保护。

这些测试使用临时目录和回环地址，不连接用户的堡垒机。真正的 SSO、一次性凭据、现场权限和 Windows 控制器集成以现场验收结果为准。
